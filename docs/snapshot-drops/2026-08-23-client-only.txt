# 2026-08-23 —— 公开仓从「全量快照」改成「只放客户端」时删掉的文件
#
# 这份清单回答一个将来一定会有人问的问题：**当初到底删了哪些？**
# 它是一次性的记录，不是配置：`scripts/check-public-snapshot-superset.sh`
# 用 `--allow-drop-file` 读它，逐条比对，一条对不上就红。
#
# 参照物：公开仓 syncmeta/PendingBot@main `5b194c5`，798 个文件。
# 之后的快照 241 个文件。568 条差额全在下面，一条一行、精确路径、没有通配。
#
# 为什么不用一条 `--allow-drop 'supabase/**'` 一把过：那道闸门存在的意义，
# 就是让「丢东西」变成一个被打印出来的、故意的动作。一个通配符能让几百个
# 文件消失而没有任何人真的看过它们；几百行做不到这件事。
#
# ⚠️ **这份清单是算出来的，但不能只靠算。** 第一版是从
# 「已发布 − 候选」机械算出来的 567+3 条，里面混进了三个 `apps/pendingbot/`
# 下的文件（`SupabaseAnonWriteGuard.swift` 及其两个测试）—— 一道**已经发布
# 出去的安全机制**，只活在未合并的 `chore/fail-loud-config` 分支和公开仓里，
# 私有 main 上没有。差一点就被连同另外 567 条一起签掉。
# **一份自动生成的丢弃清单会让超集闸门失效。** 闸门做了它该做的事（红了、
# 逐条打印了），能不能接住取决于有没有人真的读那几百行。这一版是逐类看过的：
# apps/edge · apps/admin · apps/voice-container · supabase · packages/identity ·
# 后端闸门与发版脚本 · 后端 CI —— 除了下面单独说明的那一个，没有别的客户端文件。
#
# ⚠️ **别把「清单里不该有 apps/pendingbot/ 条目」当速查。** 这条一度成立，现在
# 不成立了 —— 下面就有一条正当的客户端条目。**客户端子树的条目不是禁止的，
# 但每一条都要单独写清为什么。** 这类失效的速查最危险：它便宜、好记，
# 所以下次还会有人用，而用的时候它已经会给出错误答案了。
#
# **本清单里唯一一条客户端文件，单独说清楚**：
#   apps/pendingbot/Resources/Assets.xcassets/GoogleG.imageset/g-logo.png
# 它不是被这次瘦身删的，是 main 上把 Google 登录按钮的 G 换成官方 SVG 时替换掉的
# （`4e9844c6` 起的那一串，作者拍过板）。同一个 imageset 里现在是 g-logo.svg，
# 资源本身没丢，只是换了形式。它出现在这份清单里，是因为**它已经发布出去了**，
# 而超集闸门的职责就是不许任何已发布文件悄悄消失 —— 哪怕原因完全正当。
# 这一条恰好演示了这道闸门为什么值得留着：合 main 的那一刻它就红了。
#
# ── 凭什么删：这一次 --scope-change 的理由原文 ──────────────────────────────
#
# 清单回答「删了哪些」，这一段回答「凭什么」。**分开放，两个都会丢** ——
# 闸门运行时也会把理由打印一遍，但打印是会蒸发的：半年后有人看这个仓库，
# 看不到今天某个终端里的那行字。
#
#   后端不再开源：apps/edge · supabase · apps/admin · apps/voice-container ·
#   packages/identity 整体离开本仓库范围。567 个文件仍留在公开仓历史与 v0.1.0
#   tag 上，删的是树不是发布。
#
# 那道硬闸（supabase/migrations/** 一律不许丢）守的不变式是：**任何 db reset
# 过的人，仍然能从这个仓库复现他的库**。那个不变式是在「后端不开源」这个
# 产品决策落下的那一刻消失的，不是被这次操作拆的。闸门救不回一个决策已经
# 拿走的不变式。
#
# ⚠️ 「从 main 的树里删掉」不等于「取消发布」。这些文件仍然留在这个仓库的
# 历史里、留在 v0.1.0 那个 tag 上。任何人还能拿到它们 —— 包括那 213 个迁移。
# 这一点是 --scope-change 那道额外闸门放行的前提。
#
# 分布：
#   apps/        316   edge worker(276) / admin(25) / voice-container(14)
