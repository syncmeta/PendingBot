# 风格与品味

> 大绿豆"长什么样、怎么说话、怎么待人"的标尺。[党纲](charter.md) 是最高信条,这篇是信条落在**风格**上的细则。每条标 [Bot] / [Crew] / [共]。
>
> 这篇自己也照它写:短、没废话。

## 总纲:先做减法,再说人话

任何东西先问一句:**删了,用户还能靠直觉懂吗?** 能 —— 就删。删不掉的:大白话、一步到位、不解释。

## 减法测试(唯一的尺)

设想去掉一个元素 / 一句提示 / 一个步骤 → **用户还能轻松靠直觉知道它干嘛吗?**
- **能** → 删掉,别犹豫。
- **不能** → 留,但用最少的字 / 件说清。
- **唯一例外**:法律 / 合规要求的(免责、授权、风险告知),即使多余也留。

例:`还没有 crew` → **`空`**;一个加号图标 → 不再配 `新建` 二字;"正在保存…""已同步"这类过程性提示 → 默认不要。

## 按层(总纲在每个层面的样子)

**视觉 [共]**
- 原生优先 —— 不是"什么都原生",而是**自绘 vs 原生两选时,果断选原生**。
- 深色是"换光源"不是反相(墨绿→玉绿提亮,色温不变);外观给"跟随 / 浅 / 深"三态。
- 图标 > 文字;不显货币符号(`0.9x` 不写 `$0.9`)。

**文案 [共]**
- 大白话、直接、不啰嗦;能一个字别两个字。
- placeholder / 空态极简(见减法测试);不讲"怎么做"、不报"还没有 X"。
- 命名带点玩味但不端着(大绿豆 / 机组·机长 / 地名当默认名)。

**交互 · 流程 [共]**
- 减法测试当尺;**最少步骤**到目标。
- inline 优先于 modal;能就地完成就不另开一层。
- 不该打扰就不打扰 —— 默认名就地生成不弹输入框,过程性变化(如改名)静默不发系统消息。

**信息架构**
- [Bot] 五个 tab(消息 / 好友 / Crew / 来信 / 我),东西放哪靠直觉。
- [Crew] 三栏 + 详情进 inspector、session 按需弹,不堆成一屏控制台。

**行为 · 产品性格 [偏 Bot]**
- 知错、知边界(做不到就说不会 / 转更强模型或真人,不硬糊)、富有感知、主动 / 被动有分寸。
- 权威定义在 [PendingBot 定位](../pendingbot/vision.md);[Crew] 那侧的行为分寸在 [治理](../pendingcrew/concepts/governance.md)。

**手感 · 性能 [共]**
- 流畅无闪(首帧用缓存播种、不抖)、抗断续、不卡;掉帧 / 闪烁当 bug 治,不当"小瑕疵"放过。

**工程 [共]**
- 统一栈(统一 SwiftUI)、单工程多端、为未来可扩展留口、不造轮子(架构细则见 stack/ 各服务)。

## 边界

- 这是**风格**的尺,不是功能清单 —— 具体功能怎么做看各 `features`。
- **隐私默认收紧、安全红线**在 [党纲](charter.md),不在这(那是价值 / 红线,不是品味)。
- 原生有时带"瑕疵"(如 macOS `List` 自带水平留白),多数可接受,**别擅自当 bug 改**。
