# 群账号

群账号(`group_account`)是 [subject](subject.md) 两类之一:**一群人共担的责任主体**。这一篇只立它的**定位**——它有多轻、跟谁绑、怎么建;成员怎么分权见 [群权限矩阵](group-permissions.md)。

**逻辑**
- 群账号是一个独立的责任主体,带一个共享钱包 + 一份成员名单。它下面的 crew / 会话 / 费用全归这个群账号,而不是归某一个人。
- 几个人合用一个钱包、共管一批 crew、共同决定谁能批准操作 —— 就建一个群账号。

**为什么 —— 轻量、可临时,不是 Notion workspace**

群账号是这一篇的核心,也最容易被误解,所以单独讲清楚它的定位:

**群账号是轻量化、可临时的,跟 Notion workspace 那种"重资产组织"完全不同。** 具体表现:

- 出门旅游,几个朋友 + 一个 captain bot 临时建一个群账号整理旅游信息 —— 用完就用完,不留组织包袱;
- 家里就一台电脑共享 → 直接登录一个群账号最合适;
- 公司团队 / 项目组 → 同样的模型,**没有任何特殊处理**。

为什么这么轻:大绿豆定位是**人与 AI 协作的平台**,任何协作平台都需要"组织账号"这一层,但大绿豆的协作群体可能**非常临时**,所以它的组织账号必须比业界主流轻得多 —— 建一个群账号的成本要低到"出门旅游都值得建一个"。

**群账号不必先有一个群聊。** 它是一个独立可创建的责任主体:任何登录用户都能直接建一个群账号(自己自动成为 owner),不需要先拉一个群聊。

**用在哪·长什么样** — 在 PendingBot 里任何登录用户都能新建一个群账号、起个名字(如「五一川西」),自己成为 owner,然后把人加进来、往群钱包充点钱。之后这个群账号就能当 crew / 会话的责任主体用,也能被 owner/admin 扫码代表登录 PendingCrew(见 [设备授权](device-grant.md))。

**边界**
- **群账号 ≠ 群聊** —— 一个 `group_account`(责任主体 + 钱包 + 权限矩阵)和一个 IM 群聊是两个东西。群账号可以独立于任何群聊存在;群钱包、群成员管理都从 group_account subject 起,而不是从某个群聊起。
- **不做通用组织架构系统** —— 群账号是"轻量协作责任主体",不是企业目录 / 部门树 / 通用权限平台。

**注意**
- **"必须绑群聊"是已死的旧设计** —— 早期设计曾要求群账号必须绑定一个群聊(schema 里 `group_conversation_id` 一度非空)。现已按轻量化定位放宽:群账号可独立创建,`group_conversation_id` 允许为空,创建路径是 `grp_create_group_subject(display_name)`,不强求绑 conversation。老 plan 里"必须先有 group conversation"的说法别写回。变更出处见 [`subject-foundation.md` Spec v2 修订节](../../../superpowers/plans/2026-05-24-subject-foundation.md)。
- **"群账号 = 群聊"是设计里最常被混淆的一点** —— 看到"群钱包入口该放哪"这类问题时,记住要从 group_account subject 起,不是从某个群聊起。
