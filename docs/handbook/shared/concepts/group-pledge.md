# 群分摊与认缴

**一句话:群里花钱默认从群钱包出;往群里出钱有两种姿势——把钱真转进去(实缴),或只授权"用我个人余额顶一部分"(认缴);钱永不提现,退群 / 解散按份额退回个人余额。** 这一篇讲群层面的出钱与分摊;群钱包本体见 [`wallet-pnc`](./wallet-pnc.md),谁付钱的总规则见 [`billing-subject`](./billing-subject.md),群账号与权限见 [`group-permissions`](./group-permissions.md)。

---

## 逻辑 —— 两种出钱姿势,一套分摊

群账号有自己的钱包。往这个钱包"贡献"成本,有两种模式,区别只在"钱在哪、何时动":

| 模式 | 钱在哪 | 何时真扣 |
|---|---|---|
| **实缴(deposit / contribute)** | **真转进群钱包**(从个人余额扣,进群池) | 注资当下就转入;之后群消费从池里扣 |
| **认缴(pledge)** | **不动,留在个人钱包** | 只是个授权额度;**群消费发生时**才按比例从你个人余额当场扣 |

**群的"总份额" = 实缴池余额 + 所有认缴成员的"有效认缴"之和**,其中每人的有效认缴 = `min(你认缴的额度, 你当前个人余额)`(实时算)。每个人在群里的占比 = 自己的份额 / 总份额——**这一个数同时是你的分摊比例,也是你(实缴部分)能取出的比例**。

**一笔群消费怎么摊**:按各人份额占比拆。实缴的那部分从群池扣;认缴的那部分,实时从各认缴成员的个人钱包直扣。加起来正好等于这笔消费,不重不漏、平台不亏。

---

## 为什么 —— 设计目标(用户初衷)

这套模型是为了同时满足几条直觉上"群账该这么算"的诉求:

- **额度自动流向要扣的地方**,不需要谁手动给群里每个人分配额度。
- **一份个人余额能复用于多个群**(OpenRouter 式:一个余额到处用、先到先得)。认缴尤其支持这点——你可以给 A 群认缴 100、给 B 群也认缴 100,哪怕只有 100 余额,谁先消费谁先扣。
- **一个人欠费不拖垮整个群**:某认缴成员个人余额见底 → 他这轮的有效认缴自动变 0、退出本轮分摊,其余人按占比继续,群照跑。他不欠群钱、不连累别人。
- **能实时看到自己在群里的占比 = 可取出比例**——同一个数,公开透明。
- **钱永不提现成现金**:"取出"= 退回你的个人 PNC 余额,不是打回银行卡。

为什么不在消费时就把每笔成本按成员拆开记账?因为那样簿记会爆炸。实缴走的是一个**质押池 + 份额衰减**的模型(像 DeFi 质押池):群消费只更新池子一行(份额随之等比衰减),各注资人的"当前可取额"随之同比缩小——等价于"每人摊了自己占比那一份",但不用为每笔消费写 N 条成员账。份额记账的具体数学(两个字段、三个动作、完整算例)见 [`group-share-index`](./group-share-index.md)。

## 用在哪·长什么样

- **群钱包页**(iOS / Mac):显示实缴池余额、总份额、每个有份额成员的实缴可取额 / 认缴额度 / 当前占比;以及充值 / 认缴 / 取出 / 退群 / 解散这几个操作。
- **充值对全员开放**:owner / admin / member 都能往群钱包出钱(实缴或认缴)——群账号本就是合伙出钱(见 [`group-permissions`](./group-permissions.md) 权限矩阵)。
- **认缴的"退"= 调低或取消 pledge**(改授权,不涉及退款,因为认缴根本没预存钱)。
- **实缴的"取出"**:随时可取、可部分取(`/withdraw`),金额 ≤ 你当前可取份额;取出退回你个人余额,人还在群里。**全额取出 = 退群(`/leave`)**。

## 示例 —— 一个三人群,实缴 + 认缴混着来

群「读书会」三人:

1. **小张实缴 60 PNC**——钱真转进群池,他在群里有 60 的可取份额。
2. **小李认缴 100 PNC**——他没转钱,只授权"群里花钱时,按比例从我个人余额顶,最多顶到我认缴/余额的较小值"。
3. **小王什么都没出**——他在群里花钱不分摊(份额 0),但能正常用(群池 + 小李认缴顶着)。

群里发生一笔 30 PNC 的 AI 消费:按当下总份额(60 实缴 + 100 认缴 = 160)拆——实缴池摊 `30×60/160 ≈ 11.25`(从池扣、小张可取份额同比缩),小李摊 `30×100/160 ≈ 18.75`(实时从他个人钱包直扣)。

后来小李个人余额花到只剩 10,这时他在群里的有效认缴自动缩到 10,占比随之下降,下一笔群消费他只摊得更少——余额见底就自动退出分摊,不欠群钱。小张哪天想退,`/withdraw` 取回他当前那份(已含历史消耗衰减),或直接退群一次取完。

## 边界 —— 明确不做

- **不提现成现金**——群钱包的钱不能打回银行卡。
- **不做群内任意转账 / 指定第三方收款**——只有"实缴 ↔ 退回个人余额"这一条内部份额结算路径。
- **认缴成员没有"池中可取额"**(他没存钱)——他的"退"只能是调低 pledge。
- **认缴 / 实缴的上层切换 UI、门禁余额读取的缓存优化**等,本概念只定计费层规则,先正确后优化。

## 注意 —— 坑 & 容易混淆的点

- **⚠️ "无提现" 和 "退份额" 是两件事,别因为有 `/withdraw` 端点就以为能提现。** `/withdraw` 退的是你实缴在群里那份、退回你的**个人 PNC 余额**(平台内部),不是提现到银行卡。同理退群 / 群解散时按份额退回个人余额,也是内部结算。

- **认缴允许超额、允许多群复用、先到先得。** 给多个群认缴的总额可以超过你的个人余额——谁先消费谁先扣,另一个群下次消费时读到你余额已降、份额自动缩。这是有意的(OpenRouter 式)。极端竞态(两个群并发把同一余额扣穿)由个人 WalletDO 串行兜底,残余缺口有界(群池吸收或平台自担,记 chargeback_loss)。

- **个人 WalletDO 是认缴能成立的关键。** 每个用户一个个人 WalletDO 串行权威:本人直接消费、多个群的认缴拉取、取出入账,全经它串行,根治"多群并发扣同一余额"的双扣。群 WalletDO 仍在(管实缴池 + 群门禁 + 份额衰减)。

- **链式退款堵漏**:用户把钱实缴进群后,又去上游(Apple/Polar)退了购买款 → 不能让"钱退了、群里额度还在"。处理:按该用户在各群的当前份额从群里冲减(不返还用户,因为他拿的是上游现金),等价于"他撤回了自己那份",对其他成员公平。

- **群池漂移报警**:群池余额(公平性镜像)与 Polar 群余额应一致,偏差超 1 PNC 报警(只报警不自动改写,避免与份额失配)。

- **诚实小角**:流式回合的最终成本要等回合结束才精确,若有人正好流式中途取走,极端下池子在末笔扣款落地时可能短一点点——overdraft 缓冲兜着、新回合本就过门禁,pre-launch 可忽略(已记 tech-debt)。
