# 模型选择

bot 用哪个模型,不是建 bot 时钉死的一个 slug,而是从一个**模型池**里抽。池可以是手挑的清单,也可以是**活查询**(预设)。相关:[配置即 CMS](config-as-cms.md) · [模型盲盒](../../pendingbot/features/model-blindbox.md) · [建 bot 与预设](../../pendingbot/features/create-bot-presets.md)。

**逻辑**

- **模型池** — 每个 bot 的 `config.modelPool` 定义"这个 bot 能用哪些模型"。池由几部分并集再相减得到:价格区间窗口 ∪ 显式选中的 model 清单 ∪ 预设展开的模型,再减去排除清单,套上厂商 / 发布时间过滤。新会话**从池里随机抽一个**当作整段会话的主模型(抽定即固定,见盲盒)。
- **预设 = 活查询,不是固定清单** — 预设不预存一串 slug,而是存一条**规则**(`resolver_kind` + 参数),对话时拿着规则去**实时解析** OpenRouter 模型目录算出当前应该是哪几个模型。所以 board 把"头两家旗舰"的策略一改、或者厂商发了新旗舰,所有引用这个预设的 bot **自动跟随**,不用逐个改 bot。
- **五个预设全规则驱动,无手钉清单**:头两家旗舰(固定 OpenAI + Anthropic 各取一个旗舰)/ 中国旗舰(中国厂白名单各取一个)/ 各家最新(按发布时间)/ 速度快(按实时吞吐 + 质量下限)/ 最热门(按 LMArena 评分代理)。规则和参数都在 board 里管。
- **预设引用 vs 自定义,二选一** — 一个 bot 要么是"预设驱动(活的,跟着预设变)",要么是"自定义(冻结的显式清单)"。点"自定义"= 拿当前所选预设的并集当起点 → 进选模型页手改 → bot 转存**显式**模型池,从此**不再跟预设联动**。
- **对话时展开成模型并集** — turn 路径上,bot 存的预设 slug 被展开成它们各自解析出的模型,与显式 `models` 取并集,再走池过滤,最后随机抽一个。解析失败(目录拉不到等)就**降级回 bot 钉的兜底模型**,绝不让一轮对话因为预设算不出来而崩。
- **统一计费** — 不管抽中的是哪家的模型,推理都走 **Cloudflare AI Gateway 的统一计费**(Anthropic / OpenAI / Google 走各自的 native passthrough,其余走 OpenRouter 透传),全程不在 edge 里放任何厂商的裸 API key。模型目录本身走 OpenRouter 的**公开免鉴权端点**+ CF 边缘缓存。

**为什么**

- **配置化纪律** — 模型 slug 是会过时的(厂商月月发新款)。把"哪个是旗舰"做成规则而非硬编码清单,运营 / 产品就能在 board 改,不用等一次发版。这是党纲红线"配置走 board、不硬编码"在模型维度的落地。
- **抛弃 WorldRouter,统一收口到 AI Gateway** — 早期方案是自建路由层(WorldRouter)逐家对接计费;现已彻底转向 **CF AI Gateway 统一计费**:一处 `cf-aig-authorization`、一份账单、零裸 key。OpenRouter 退成两个角色——**目录的公开数据源** + **没有 native passthrough 的长尾模型的透传后端**,不再是计费主路径。
- **实测推翻文档** — 预设的数据源是直接打真实 OpenRouter API 实测定的,不是照文档写的:稳定版目录的 `order=` 排序参数对 API 完全无效(只是网站前端的);用量排行榜要 OpenRouter 私钥(edge 没有也决定不加)。所以"最热门"用 LMArena 评分当代理(语义=评测质量榜,不是真实使用量榜),"速度快"逐个拉 per-model 端点的近 30 分钟吞吐。

**用在哪·长什么样**

- **建 bot 第一屏**:几个预设多选(默认勾前三),点进去能看每个预设当前展开成哪些模型;一个"自定义"入口进选模型页。用户看到的是"头两家旗舰""速度快"这种人话,不是 slug 列表。
- **对话里**:抽中哪个模型用户默认看不到真名(盲盒藏成 `PendingModel`,见模型盲盒),除非 bot 设成"直接披露"。
- **board**:模型预设管理页(改 `resolver_kind` + 参数 + 开关 + 默认勾选);系统模型角色管理页(见下"边界")。

**示例** — 你建了个 bot,勾了"头两家旗舰"。今天它解析出 `claude-opus-4.8` 和 `gpt-5.5`,会话抽中其一。下个月 Anthropic 发了新 opus,board 不用动——预设规则是"anthropic 的 claude-opus 系列里发布日最新的非小号版本",新 opus 一进目录就被自动选中,你这个 bot 下次新会话就可能抽到它。整个过程你没碰过 bot 设置。

**边界**

- **系统模型角色不在这套池 / 预设里** — "给会话起标题的小分类器""群聊唤醒路由""识图摘要""语音默认模型"这些是**平台自己的系统任务**,用的模型由一套独立的**模型角色**配置决定(board 的 model-roles 页,KV 下发),不走 bot 的 `modelPool` / 预设。两者别混:预设 / 池 = 用户的 bot 用哪个模型;模型角色 = 平台后台任务用哪个模型。
- **不做"性价比"预设**(用户明确先不要)。
- **预设不引入新计费 / 可见性档位** — 只是换"池来源",计费和可见性逻辑不动。

**注意 — 已死的旧方案(别写回)**

- ❌ **arena 模型评测**(A/B 盲投 + Bradley-Terry 个人排行榜)——已退役。本篇讲的"从池里随机抽一个"是它留下的内核;面向用户的壳已转型成**模型盲盒**(猜模型的娱乐玩法,见 pendingbot features),不再是评测。
- ❌ **WorldRouter 自建路由计费** —— 已弃,改 CF AI Gateway 统一计费;OpenRouter 降为目录端点 + fallback 透传。
- ❌ **系统 model slug 硬编码在调用点** —— 已收进 board 的 model-roles(KV),空 KV = 旧行为(每个角色的 code-default 与旧硬编码逐字节相同),board 覆盖数秒全球生效。
- ⚠️ **旗舰策略曾默认"最贵"** —— 实测发现"最贵"会选到旧款 / 蒸馏小模型(混合成本估算不等于档位),已改成"系列内发布日最新"(`latest_in_series`),锚每条产品线的 series 前缀取最新非小号版本。这带来一条命名漂移尾巴:新大版本(如 gpt-6)或新厂商的小号命名要补 seed / 排除集,见 tech-debt。

**现状** — 🟨 **预设系统代码全落 + 已部署 prod**,端点侧真验通过(`GET /v1/model-presets` 返回真旗舰)。**尾巴**:① iOS 登录态模拟器 / 真机走一遍(点预设看模型、秒开、建删 bot)未做,不在 build / 端点绿就判 done;② 改预设数据(迁移 / db push)不会自动失效 KV 缓存,部署 runbook 要手动 bust(2026-06-19 实际踩到);③ "最热门"是评测质量榜非真实使用量榜;④ 速度快候选 cap / 质量下限是拍的、未长期观察。统一计费(AI Gateway)与目录缓存为 ✅(随读路径上线)。
