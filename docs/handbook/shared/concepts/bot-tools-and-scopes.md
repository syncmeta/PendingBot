# 工具系统

bot 能做的事——查长记忆、搜历史、读图、跑代码、上网搜——都是**工具**。哪些工具能上、在哪个场景上、模型看到的工具说明长什么样,统一由一张**工具注册表**管。相关:[配置即 CMS](config-as-cms.md) · [Prompt 与世界观](prompts.md)。

**逻辑**

- **一张注册表,管住所有工具** — 不管一个工具背后是 edge 自己的代码(**native**),还是转发给一个外部 MCP 服务器(**mcp**),它都在同一张 `tools` 注册表里有一行。这张表是"这个工具到底允不允许出现在模型面前"的唯一开关。
- **scope = 工具出现在哪个场景** — 每行带一组 `scopes`:`chat`(日常聊天回复)/ `envelope`(来信探索阶段)。一个工具可以同时挂在多个场景(大多数 native 工具两个都挂)。组装某一轮的工具清单时,只放该场景授予的工具。
- **能力按 scope 授予,kill-switch 不用发版** — edge 在组装工具清单时,拿这张表(60 秒缓存)过滤一遍:表里 `enabled=false` 的行直接不给模型看。在 board 关掉一行,一分钟内全球生效,**不用部署**。
- **native 与 mcp 两类** — `native` 的派发是 edge 自己的代码;`mcp` 的派发是转发给某个上游 MCP 服务器(注册表行指向那台服务器)。关键差别在于:同一台 MCP 服务器可能上报很多工具,但运营**只勾选想暴露给模型的那几个**——注册表是这道筛子。
- **模型看到的说明也归注册表(可热改)** — 每行带一个 `model_description`:模型实际读到的那段工具说明。对 native 工具这是**唯一真相**(edge 的工具定义里故意不写 description,组装时把注册表里的值换进去),所以改一句工具说明走 board、不用碰代码。对 mcp 工具是可选的:留空就用上游 MCP 服务器自己的说明。
- **失败 fail-open** — 注册表读不到(DB 抖动)时,过滤这一步直接跳过、放行原始工具清单。理由:一次 DB 闪断把每个工具都从模型那剥掉,比 kill-switch 慢一点更糟。

**为什么**

- **统一面板 + 配置化** — 把"有哪些工具、各在哪个场景、模型看到的说明是什么"收进一张表 + 一个 board 页,运营能一处看全、一处开关 / 改文案,符合党纲"该可改的进 board"。
- **native / mcp 同表但不同派发** — v1 这张表只是**过滤 + 元数据层**,不是运行时派发器;native 走代码、mcp 走转发的派发路径不变。表的职责窄而清:管"允不允许"和"模型看到的说明",不管"怎么执行"。
- **工具说明是 prompt 的一部分** — 模型读到的工具 description 直接影响它调不调、怎么调,属于该可热调的运营文案,所以和别的 prompt 一样从代码里抽出来(这里抽进注册表行,而非 Langfuse,因为它和工具开关同表更顺手)。

**用在哪·长什么样**

- **运营侧**:board 的"工具管理"页——列出每个工具(native + mcp 一张表),开关 enabled、改 `model_description`、给 mcp 工具勾选要暴露哪些。**只读 + 改,不建不删**(行的增删跟着代码 / MCP 服务器走,不在 board 凭空建一个没有 handler 的工具)。MCP 服务器本身另有一个 board 页全量 CRUD。
- **用户侧**:用户不直接看这张表;他们感知到的是"这个 bot 会不会上网""会不会主动弹个跑代码的确认卡"。有些工具还有**条件暴露**(例:群昵称工具只在群里给、免授权跑代码要 skill 显式开启)——这层条件留在代码里,注册表只答"这工具允不允许 + 在哪个场景"。

**示例** — 你想临时停掉所有 bot 的"识图"能力(比如识图模型在涨价)。运营进 board 工具页,把 `read_attachment` 那行 `enabled` 关掉。一分钟内所有 isolate 的缓存过期,组装工具清单时这个工具不再出现在任何模型面前,bot 自然就不再读图——全程没发版、没改代码。想再开回来同理。

**边界**

- **注册表不是派发器** — 它过滤 + 提供说明,不决定"怎么跑"。native 工具跑 edge 代码,mcp 工具转发上游,这条派发链不在表里。
- **条件暴露留在代码** — "群里才给""skill 开了才给"这类与运行时上下文相关的判断在代码里,注册表只表达静态的"允许 + 场景"。
- **scope 只有两个**(`chat` / `envelope`),不是任意自由维度;新增场景要同时改组装路径。

**注意**

- 老的 `pendingbot.tools` 表(来自最初的 init)从没接进 edge 运行时(无代码读它),已被**删掉重建**成现在这张过滤 + 元数据表,别把那张旧表当回事。
- 模型盲盒引入的 `prompt_model_guess` 也是一条 native 工具行(`kind=native`,`scopes=[chat]`),走同一套注册表 kill-switch——说明"让 bot 主动弹个猜模型卡"也是一条可在 board 关掉的工具。
