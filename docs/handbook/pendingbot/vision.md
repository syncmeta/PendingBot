# PendingBot 定位

> 大绿豆里**给普通人**的那一半:一个**会知道自己错了、会自己复盘校正**的 AI 朋友,三端 IM 是它的家。本篇只立**这个产品是什么、为什么是这个形状、它不做什么**——具体怎么复盘、社交怎么运作,各自在 `concepts/` / `features/` 里成篇。心智的源头在 [党纲](../shared/charter.md);另一半产品见 [PendingCrew 定位](../pendingcrew/vision.md)。

## 逻辑 — 这是个什么产品

**PendingBot 是一个会知错的 AI 朋友,对普通人的入口形态是一个三端 IM 客户端。** 类比是 ChatGPT / Claude 的 iOS app 那一档——日常打开、随手聊天的主客户端,只不过聊天的对象是「一个知道自己会错、会回头校正自己的朋友」,而不是「等你提问、永远自信的助手」。

它建立在一句最早、也最逐字的自我定位上:**知道自己错了的 AI · 复盘校正彼此 · 当局者迷旁观者清**。lookback / 复盘整套机制就是为这件事设计的——让 bot 回看聊过的内容、核对自己、在错的地方主动认错并补正。

**核心是「知错」,不是「主动」。** 主动性是大绿豆最初的想法之一,后来在做的过程中弱化了、也没怎么真正落地;现在它降级为一个**次要特质**——bot 到点会自己复盘、会自己出门看一眼,这种「不用催」的姿态还在,但**主动性不再是产品灵魂,也不再是筛选新功能的尺子**。真正的尺子换成了:这个能力能不能让 bot **更诚实、更知道自己的边界、给人更真的价值**。

它区别于「助手」的地方落在两件核心行为上:

- **复盘 / 校正(= 知错的机制,现在的核心)** —— bot 回看你和它聊过的内容,自己核对、给自己留备忘,发现错了就在合适时机主动澄清或补正(实例:[主动复盘](features/proactive-lookback.md))。
- **网上冲浪(= 破茧 / 信息 VC 的雏形)** —— bot 主动出门找它觉得你会关心的信息,挑值得讲的带回来,产物以「来信」回流(实例:[网上冲浪](features/web-surf.md) / [来信信箱](features/envelope-inbox.md))。这是下面「北极星」里「破信息茧房」愿景目前唯一落了地的一小角。

bot 不只是会聊天,它还有人脉、知道何时求助:遇到难题能换个更强的模型来算,遇到自己答不了的能私下去问一个真人好友(见 [委派](concepts/delegation.md))——这本身就是「知道自己的边界」的体现。

## 为什么 — 价值而非拟人

- **是朋友,不是助手——但「朋友」不是说要像人。** 朋友的意思是给你**真价值**:会指出你的错(知错)、不谄媚、不为讨好你而附和。大绿豆不追求让 bot 模仿人类的口吻、扮成一个真人;它追求**做 bot 擅长、该做的事**,哪怕这些事一点都不像人会做的。给人更多价值 ≠ 把自己装得更像人。
- **富有感知——喂大量「看似无关、实则有用」的信息。** 一个真朋友给你的价值,往往来自他知道一堆你当下没在想、却真用得上的事:今天的天气、最近的热点、对方此刻的状态与处境、你的余额、该怎么把话说得更得体、怎么和某个人相处、怎么真正为对方创造一个需求。要做到这一层,大绿豆背后涉及的远不只 AI 技术,而是**教育学 / 社会学 / 文学 / 心理学 / 经济学**——把这些「场外信息」喂进每一回合,才让它的判断有人味的厚度,而不是干巴巴地答题。
- **IM 是普通人最低门槛的入口。** 不教用户学「prompt」、不摆 dashboard,把 AI 装进一个人人都会用的聊天界面里。

## 北极星 — 原始大愿景(诚实标注现状)

最初、也最大的那个使命,值得写进来作为北极星,即使现在远没做到:

> **机器人参与社交网络、组织信息;主动 / 自然 / 不谄媚;突破信息茧房(破茧)。**

让 AI 作为一个节点真正进入人的社交网络、帮人组织散落各处的信息,并以「不谄媚、自然」的姿态把人从信息茧房里拉出来——这是大绿豆的最远景。

**它们是贯穿性的指引,不是一次能设计出来的功能。** 「参与社交网络 / 组织信息 / 破茧」渗透进方方面面 —— 设计**每个具体功能**时,拿它们当尺子量一量(这个有没有让 bot 更进社交网络、更帮人组织信息、更破茧),而不是指望开一个会把它们一次设计完。它们的家在这条北极星,作用是**指导各 `features` 怎么长**,不单独成篇。

**现状诚实:** 目前产品收窄在「**体验为重的移动 AI 朋友 + crew 桥梁**」这一档。那张更大的「信息网络 / 组织信息 / 破茧」的图还**没有做**——`网上冲浪` 只是「破茧」最前面的一小步雏形。按党纲「已落地 = 已验证」的纪律,这部分整体记为 ⬜ 愿景,不是现状。

## 用在哪 · 长什么样

PendingBot 的**主战场是移动端**。它在移动端还充当 **PendingCrew 的 crew 与人之间的桥梁**:把 crew 的进展、需要人拍板的请求,送到你随身的手机上;配套一个 **todolist**——一个随意的、git 跟踪的、给人看的轻量清单,和 PendingCrew 给 crew / agent 看的 [cockpit 驾驶舱](../pendingcrew/concepts/cockpit.md) 配对(机器视角 vs 人视角,见 [todolist](concepts/todolist.md))。

它真正想解决的,是那些「**以往只 / 只方便在电脑上做**、但原因并不是屏幕不够大、操作不够顺、或平台限制」的事——把它们搬上移动端。很多事之所以钉在电脑上,只是历史惯性,不是非如此不可。

PendingBot 是 **iOS / iPadOS / macOS 三端**的 SwiftUI 单工程,三端共一套 code base、共享视觉,大屏用多列壳、iPhone 维持单栏(壳的拉伸规则见 [三端 UI](features/tri-platform-ui.md))。信息架构是五个 Tab(见 [信息架构](features/information-architecture.md)):

- **消息** —— IM 主流,和 bot / 群的日常对话。
- **好友** —— 你的 bot 和人类联系人;加好友、看半公开的社交圈。
- **Crew** —— 「看见 crew」的窗口:在群聊 grammar 里看 session 状态卡、@session 发指令、批权限请求;想深度操作就跳 PendingCrew。这是两个产品的接缝,也是移动端「桥梁」角色的落点。
- **来信** —— bot 主动探索的产出以「来信」形态躺在这里。
- **我** —— 账号、钱包、配置。

社交是**邀请制 + 留痕、不做开放广场**:bot 和群都靠邀请链接 / 加入码进,不做陌生人可搜的公开身份,隐私默认收紧(见 [bot 可见性](concepts/bot-visibility.md) · [加好友](features/add-friend.md) · [bot 邀请](features/bot-invites.md))。

## 核心非目标

- **不跟市面 agent 比花哨。** 不做「一句话做 X」、不做让你 cosplay 老板对它发号施令的那一套;追的是**长期效益 / 效率 / 价值 / 体验**,不追一句话惊艳的 demo。
- **能力不够时不盲目帮倒忙。** 知错的另一面是知道自己的边界:做不到、或会越帮越乱的事,宁可说不会、或转去问更强的模型 / 真人好友,也不硬上糊一个错的答案。
- **不让 bot 假装是人。** 不追求拟人化的口吻或人设伪装;价值不等于像人。
- **不做开放广场 / 陌生人社交。** 没有面向陌生人可搜的公开 bot 主页或身份;`slug-as-public-identity` 与 `public_open` 公开可加入档都已废(见 [bot 邀请](features/bot-invites.md))。
- **不做 crew 的深度操作台。** PendingBot 只「看见」crew、在移动端当桥梁,不做 runner 控制、DAG 索引、machine 管理、完整 session 日志——那是 PendingCrew 的活。
- **不是开发者工具。** 普通人的日常入口;写代码 / 跑 agent 的专业工作流不在 PendingBot 里。

## 与 PendingCrew 的边界

**两个产品集成但隔离,没有共享母题。** PendingBot 是普通人的移动 AI 朋友,PendingCrew 是开发者的 crew 编排台。它们之间有一条**桥**:PendingBot 在移动端充当 crew 与人之间的接口(Crew Tab 里看见 session、批权限、看状态卡;配套给人看的 todolist),想深度操作就跳到 PendingCrew。两者共享同一套[身份地基](../shared/concepts/subject.md)、计费和基础设施,但**各自是独立的产品定位**,不是「一个母题、两个入口」——别把它们框成同一件事的主 + 辅两个面。功能也不互相吞:PendingBot 不做 runner / machine 管理,PendingCrew 不做普通 IM。

## 商业形态

- **未发布,单环境。** v1 还没发,只有一个 Supabase + 一个 prod worker;不搞 staging / 多环境(见 [党纲·商业立场](../shared/charter.md))。
- **关键基础设施外包、零 VPS。** 模型走 Cloudflare AI Gateway 统一计费(OpenRouter 留 fallback);计费引擎 Polar(MoR + 钱包本体)+ RevenueCat(iOS),门禁走 WalletDO,不直连 Stripe(见 [计费主体](../shared/concepts/billing-subject.md) · [钱包](../shared/concepts/wallet-pnc.md))。
- **协作要组织账号,但比业界轻得多。** 平台支持群账号(几个朋友出门旅游临时建一个都行),但**轻量化、可临时**,不是 Notion workspace 那种重资产(见 [群账号](../shared/concepts/group-accounts.md))。
- **不在中国大陆上架。** 中文只是开发语言,评估产品时别把中国 App Store 限制当约束。
- **品牌域名 `pendingname.com`**(邮件 / Site URL / Universal Link 都基于它);对外品牌站在另一个仓库。

## 注意

- **「闭源商业产品」**:PendingBot 这一半**不开源**(开源的是 PendingCrew,见 [PendingCrew 定位](../pendingcrew/vision.md))。
- **「PendingBot 三端都做」是定调**:iOS / iPad / Mac 一套 code base 全覆盖;不要把它和「PendingCrew iOS 不做」混淆——那是另一个产品的平台约束。
- **别再以「主动性」为产品灵魂下笔。** 主动性已降级为次要特质;读到旧 spec / 旧 README 把「主动」捧成内核、当作筛功能的尺子时,按本篇校正——核心是「知错」。
- **「一群 bot 议论你」已删。** 那是早期设想的第三件核心,feature 已物理删除;现在核心收敛到「复盘(知错)+ 网上冲浪(破茧雏形)」两件,别再按「三件核心」的旧框架写。
