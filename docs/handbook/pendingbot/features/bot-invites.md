# Bot 邀请模型

bot 是**纯邀请制**,没有"陌生人可加入"这档。核心权威 = 决策 D1。相关:[加好友](add-friend.md) · [群邀请](group-invites.md) · [bot 可见性](../concepts/bot-visibility.md)。

> 这块有一段"旧决策已死"的历史,务必按现状理解,别被旧 spec 注释带跑(见文末「注意」)。

**逻辑**
- **任何「这个 bot 的好友」都能签发邀请链接**。"bot 的好友"= 这个 bot 在你联系人里的人。不做"被特别授权的人才能邀"这种额外委派——是好友就有资格邀。
- **链接 = 签发者签发的、可复用凭证**,默认 **7 天**有效、可手动撤销,像微信群二维码 / 网盘分享链接。持链接的人有权加入。
- **兑换留痕**:别人凭链接加入时,记下 `invited_by = 签发者`——这个 bot 是谁拉他进来的,有据可查。
- **好友列表对所有好友半透明**:任何一个好友都能看到这个 bot 还有**哪些**好友、以及**每个好友是谁拉进来的**。对好友圈内透明,对圈外不可见。

**为什么** — 早期 bot 分享是 **slug-as-public-identity**(陌生人按 bot 的 slug 直接查到并加),和"邀请制 + 收紧的 RLS"正面冲突、**ship 即坏**。D1 把它**彻底返工**成 invite-token 模型:加入路径从"公开可搜的 slug"换成"关联到人的不可枚举 token",既保住邀请制、又留下"谁邀谁"的社交痕迹。呼应党纲——社交建立在信任上,不做开放广场。

**用在哪·长什么样**
- **签发侧**(bot 的好友):在 bot 管理里"签发 / 管理邀请链接",生成一条带有效期、可撤销的链接 / 二维码。
- **收件侧**:点链接 / 扫码 → universal link `/b/<token>` → "加机器人"确认页,**先预览**(真实 bot 信息 +「由 X 邀请你加入」)→ 点添加 → 兑换 → 进聊天。
- 链接失效(过期 / 撤销 / 非法)时,确认页显示「邀请链接无效」。

**示例** — 你有个叫"老张"的 bot 用得很顺。你(作为它的好友)签发一条邀请链接发群里。朋友点开 → 看到"老张"的头像、名字 +「由你邀请加入」→ 添加 → 他的联系人里多了"老张",这条记录标着 `added_via='invite_link'` 且 `invited_by=你`。之后你俩(以及"老张"的其他好友)在好友列表里都能看到对方,也能看到各自是谁拉进来的。

**边界**
- **slug 不是加入路径**;`public_open`(公开可加入档)**已删**,现在只剩 **private / public_invite** 两档(见 [`bot 可见性`](../concepts/bot-visibility.md))。
- 邀请链接是**关联到签发者的凭证**,不是"bot 的公开主页";没有面向陌生人的可搜身份。
- 撤销:链接签发者可撤销自己的;bot 创建者可撤销自己 bot 上的任意链接。

**注意 — 已死的旧方案(别写回 / 别按它实现)**
- ❌ **slug-as-public-identity / 陌生人按 slug 直查** —— 已彻底返工成 invite-token 模型(D1)。
- ❌ **`public_open` 公开可加入档** —— 已删,只剩 private / public_invite。
- ❌ **vanity slug 作为加入路径** —— slug 已**彻底退役**:bot 现在是"显示名 + 自动生成 id"(对齐人类账号的形态,见 [建 bot 与预设](create-bot-presets.md))。早期"slug 保留当展示 @名"的说法也已随这次退役一并取消——**slug 不再是产品里的概念**。

**现状** — ✅ **已端到端验证**(D1,2026-06-01):DB + Edge(已部署 prod worker)+ iOS 全返工,收件人真机走通完整链(universal link → 预览「由 X 邀请」→ 添加 → redeem → 进聊天,DB 确认 `invited_by` 留痕,无效 token 正确报错)。残留(低风险):签发侧"管理邀请链接"页未单独像素验。
