# 加人类好友

人和人之间是**申请—同意**制(像微信)。社交建立在信任 + 留痕上,不做陌生人可搜的公开身份(见 [`shared/charter`](../../shared/charter.md))。相关:[bot 邀请](bot-invites.md) · [群邀请](group-invites.md) · 隐私底线见 [头像/昵称可见性](../../shared/concepts/avatar-visibility.md)。

**逻辑**
1. **查找** — 用对方的 **handle(隐私号)** 查;查找只回**头像 + 昵称**,不回邮箱 / 注册时间,刚好够确认"是我要找的那个人"。
2. **申请** — 发好友申请,可附一句**验证语**(对方在同意前看到)。
3. **同意即进聊天** — 对方点同意,双向好友成立,直接能开 1v1 会话(两人之间的会话全局只有一个,反复点进的是同一个)。

两条进入路径:
- **handle 路径** — 扫码 / 输号码,经隐私号查到人;申请会**记住你从哪个 handle 进来的**(对方看得到),为多隐私号管理留痕。
- **同群路径** — 群聊里看到非好友成员,直接"加他好友";不经 handle,但**服务端校验你俩确实在同一个群**——否则光猜一个 user id 就能发骚扰申请。

**为什么** — 默认收紧隐私:不暴露可被陌生人直查的身份,加人必须经对方点头;验证语让对方有上下文决定收不收,而不是来者不拒。

**用在哪·长什么样** — 加好友页输完号码先**预览**(头像 + 昵称)再发申请;好友 tab 有"好友申请"分区(同意 / 拒绝);同群加好友是群成员列表里的一个动作。好友的本地备注(别名)各记各的——你给对方起的备注只你自己看见,改了不影响对方那边。

**示例** — 你在博客挂了隐私号 `blog`。某人扫码 → 看到你的头像和昵称 → 发申请附"我是看了你那篇文章的读者" → 你在好友 tab 看到这条带验证语的申请 → 同意 → 你俩成好友,他这条记录上留着"via blog"。

**边界**
- 查找**只回头像 + 昵称**,不做"按昵称模糊搜人",不回任何额外 PII。
- 同群加好友**必须**带上来源群,服务端两头校验在群,不接受裸 user id。
- 不能加自己;已是好友再加 → 直接回"你们已经是好友"并跳到已有会话。

**注意**
- **双向待定捷径**:如果对方其实已先给你发了申请,你这边再发不会叠第二条反向申请,而是**自动接受对方那条**(契合"两人同时想加对方"的心智)。
- 隐私号查找端点有**限流**(同 handle 查找桶),挡批量枚举——一次次 404 也会确认"这号注册没"。
