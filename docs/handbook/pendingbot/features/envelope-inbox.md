# 来信(Envelopes)

bot **主动给你写信**:它读你俩的聊天、上网查、写成一篇文章,放进「来信」tab。是党纲「主动性是内核」最直接的产物之一——不用催,bot 自己动笔。互为好友的真人之间也能用同一条信道写信。相关:[主动性](../concepts/proactivity.md) · [网上冲浪](web-surf.md) · [信息架构](information-architecture.md)。

**逻辑**

- **一封来信 = 一次 bot 的探索 + 写作**。触发后,bot 以「这个 bot 写给这个用户」的身份,读你俩**跨会话**的全部聊天记录(不限于某一个会话),按需上网搜索 / 抓网页,最后写成一篇带标题 + 摘要 + 正文的文章。
- **两个角色,一主一辅**:
  - **主探索者(explorer)** —— 主力。规划、搜索、抓网页、记笔记,自己决定何时「停止探索」转入写作。
  - **协作者(collaborator)** —— 可选的「另一个声音」,每轮给主探索者一句简短回应(像旁边有个同伴一起琢磨),提供新角度、推一把。可关(留空 = 不带协作者)。
- **写作是单独一相**:只有主探索者**主动喊停**(stop_exploring)时才进入写作相,用攒下的笔记 + 聊天记录写文章。撞到轮次上限 / 时间墙而非主动停的,不强行凑一篇。
- **空信不落库**:聊天素材太少(凑不出两条有效消息)、或写出来是空 / 过短 / 只有静默标记,这次来信**直接删除、不进 tab**——宁可不写,不写废话。
- **过程留痕**:每一轮主探索者干了什么(思考、调了什么工具、协作者说了什么)实时落进运行记录,详情页能回看「它是怎么想的」这条思考链。

**为什么** — bot 是「会主动关心你的朋友」,不是等你提问的工具。来信把「主动」做成一件看得见的产物:它真的去读你、去查资料、写一封信给你。多模型(explorer + collaborator)不是为了堆功能,是模拟「一个人一边查一边有同伴搭话」的探索过程,产出比单模型独白更有层次。

**用在哪·长什么样**

- **来信 tab** —— PendingBot 的主 tab 之一。倒序 feed,每行一封信(标题 + 摘要);点进去看正文(markdown 渲染) + 可展开的思考链(主探索者逐轮做了什么)。
- **触发**:用户在某个 bot 会话里手动触发一封,或由系统按主动节奏自动触发(`trigger=user`/`auto`)。
- **进行中**:触发后立即返回,客户端订阅实时进度,详情页随轮次推进「滴答」更新(它在思考 / 正在搜 X / 协作者在说…),可中途取消。
- **配置**:每个 bot 可调来信的 explorer 模型 / collaborator 模型 / 轮次上限 / 历史 token 预算占比;留空则跟随 board 配置的系统默认角色(envelopeExplorer / envelopeCollaborator)。

**示例** — 你这周跟「老张」bot 聊了几次健身计划和膝盖旧伤。系统到点自动触发一封来信:主探索者翻你俩的聊天,发现「膝盖 + 力量训练」是核心,上网查了几篇康复训练资料、记下要点,协作者在旁边提醒「别忘了他提过想跑半马」,主探索者补查跑步与膝盖的注意事项,然后停止探索、写成一篇《给膝盖留余地的力量计划》。你打开来信 tab 就看到这封信,点进去能看正文,也能展开看它一路是怎么查、怎么想的。

**真人来信** — 互为好友的两个真人之间,也能在 1:1 会话里手写一封信发给对方,走的是同一套来信信道、出现在对方的来信 tab。和 bot 来信形态一致(标题 + 正文),但没有探索过程,是即时写好的。**门槛**:只能发给**互为好友**的人(服务端 + RLS 双重把关),不能给自己写。

**边界**

- **不是聊天**。来信是「一篇文章」,不是会话里的一条消息;它有自己的 tab 和详情页,不混进聊天流。
- **不强行产出**。素材不足 / 写空了就不落库——来信 tab 里看不到「这次没写出来」的占位,失败是静默的。
- **真人来信只在好友之间、只在 1:1 会话里**。群里不能写信给某人;非好友写信被拒。
- 来信 tab 的列表只显示**收到的**信(bot 写给你的 + 别人寄给你的);自己寄出去的不在这个列表里回显。

**注意**

- **命名变迁**:这个功能内部早期叫 **scroll(奏折)**,后来重命名为 **envelope / 来信**。旧 scroll 命名仍残留在个别历史数据上(老的审计行 `task_type='scroll'`、历史注释里的「奏折」),不是新概念——以「来信 / envelope」为准。
- **历史是跨会话的**:来信读的是「这个 bot 与这个用户的全部聊天」,不是单个会话。早期实现曾把它钉死在一个 `conversation_id` 上,那是设计残留、已放开。
- 搜索 / 抓网页的供应商**不再可配**:统一走 MCP → Exa 托管服务,旧的 `searchProvider`/`scrapeProvider` 配置键在读取时被忽略。

**现状** — 🟨 代码已落、已部署(来信信道 + 真人写信端点都在 prod worker)。bot 来信主路径在线上跑过;真人来信(`/v1/envelope/letter`,互为好友门禁)代码在,端到端真机视觉验证尚未单独留证。属常规可用范围内的成熟功能,标 🟨 是因为没有专门的端到端验证留痕记录。
