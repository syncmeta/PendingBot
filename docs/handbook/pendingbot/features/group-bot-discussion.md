# 一群 Bot 议论你

把你日常聊的几只 bot 拉进一个群,让它们**多角度地议论你**——每只 bot 带着它对你的不同侧写发言,像几个了解你的朋友凑一块儿聊起你。是大绿豆三件核心主动能力之一(复盘 / 校正、网上冲浪、一群 bot 议论你)。相关:[主动性](../concepts/proactivity.md) · [bot 社交图谱](../concepts/bot-social-graph.md) · [主动复盘](proactive-lookback.md)。

**逻辑**

- **多只 bot,一个话题:你**。日常和你有来往的几只 bot 被拉到一起,各自从自己积累的对你的了解出发,从不同角度旁观、评点你——一只可能更懂你的工作、一只更懂你的生活,凑一块儿能拼出单只 bot 给不出的立体视角。
- **是"议论"不是"问答"**。重点是多角度的旁观与碰撞(它们之间也能你一言我一语),不是你提问、它们轮流答。
- **共养一只 bot**:朋友之间可以**共同拥有 / 共用同一只 bot**——同一只 bot 同时是你和朋友的好友,于是它对你俩都有了解,也成了"它议论你 / 议论你们"的素材来源。这部分(把一只 bot 分享给朋友)由 [bot 邀请](bot-invites.md) 这条已有的信道支撑。

**为什么** — 单只 bot 看你总是偏的——它只见过你跟它聊的那一面。多只 bot 各执一隅、放到一起议论,才逼近"一群了解你的朋友怎么看你"。这是把"主动 + 多视角"推到极致的一种产品形态:不止一个朋友主动关心你,而是一桌朋友一起。呼应党纲"是朋友不是助手""主动性是内核"。

**用在哪·长什么样**

- 形态上是一个**多 bot 的群会话**:几只 bot 在群里围绕你展开议论,你可以旁观、也可以插话。
- 触发上属于"到点自己做"那类主动能力——理想形态是不用你张罗、系统按节奏把合适的几只 bot 凑一桌。

**示例** — 你平时跟三只 bot 来往最多:一只陪你聊代码、一只聊健身、一只聊看的书。某天它们被拉进一个群议论你:聊代码那只说你最近明显在赶一个 deadline、状态绷得紧;聊健身那只接话说你这周训练记录确实掉了;聊书那只补一句你上次提到想读点"慢下来"的东西却一直没动。三个角度拼到一起,是任何单独一只都给不出的、关于"你最近是不是太紧了"的旁观。

**边界**

- **不是普通群聊**。普通的人 + bot 混合群是另一套(见 [群邀请](group-invites.md));"一群 bot 议论你"的主角是**多只 bot 对你的多角度议论**,定位不同。
- **不替代复盘**。复盘是单只 bot 回头审视你俩的对话;议论是多只 bot 横向拼视角——两件事互补,不重叠。

**注意**

- **当前现状是"规划",不是已实现**。代码里给这种 bot 议论会话**预留了会话类型**(`discuss`,单 owner 会话类型之一),但**还没有对应的运行体 / 编排逻辑**——它只是个占位枚举,别误以为已经有一条活的"议论会话"管线在跑。
- **不要和 `ask_friend` 这条已落地的机制混为一谈**。现已实现的是一个相关但不同的能力:**公有 bot 可以主动去问你的某位真人好友一个问题**(`ask_friend`),在那位好友的会话里聊出答案后再(`submit_inquiry_answer`)把结论带回给你。那是"bot 替你向真人打听",**不是**"一群 bot 议论你"。两者都属 bot 社交图谱的范畴,但目标和形态不同;写本主题时别拿 ask_friend 的实现去填"议论"的现状。
- **"共养一只 bot"是已落地的那一半**:把 bot 分享给朋友、让它同时是你俩的好友,走 [bot 邀请](bot-invites.md) 的 invite-token 信道,这部分可用;"多只共养的 bot 凑一桌议论你"才是尚未实现的部分。

**现状** — ⬜ 规划。会话类型已预留(`discuss`),但议论会话的编排 / 触发 / prompt 尚未实现,无 cron 也无运行体。已落地的相邻能力:**共养 bot**(经 bot 邀请,可用)、**`ask_friend` 跨好友问询**(代码已落、bot 替你向真人好友打听并带回答案;属 bot 社交图谱,与"议论"是两回事)。
