# Bot 人格

> 一个 bot「是谁」由几样东西合成:模型池 + 人格记忆 + 时区 + 一份配置 blob。这里讲的是 bot 这个产品对象的**构成与生命周期**;具体到「怎么建一个 bot / 预设长什么样」见 [建 bot 与预设](../features/create-bot-presets.md),「怎么藏模型让人猜」见 [模型盲盒](../features/model-blindbox.md)。

**逻辑**

一个 bot 不是「一个固定模型 + 一段 system prompt」。它是这几层的合成:

- **显示名 + 自动生成 id** —— bot 对齐人类账号的形态:用户给它起个名(`display_name`),系统配一个不可枚举的 id。**没有 vanity slug、没有可搜的公开 @名**(见文末「注意」)。
- **模型池(model pool)** —— bot 默认不锁死在某一个模型上。创建者可以给它配一个**池**:一段价格区间(滑杆)、一组显式点名的模型、一组**预设引用**(`presets`)、加上排除项 / 厂商 / 发布窗口过滤。新会话开起来时,从这个池里**抽一个**当本轮主模型。池为空 / 没配池 → 退回 bot 钉死的那个 `model_id`。
- **人格 / 记忆** —— bot 对自己的全局自我认知(被动观察沉淀,Honcho)、对「这个用户」的本地心智、bot 给自己写的「怎么跟这个人相处」的私人手记。这些是**长出来的**,不是建 bot 时填的表单字段;冷启动没有时退回一段身份探索的引子。
- **时区(tz)** —— bot 自认为「身处」的 IANA 时区。**只对公有 bot 有意义**:它进系统提示让 bot 有时间自我意识、也当群里调度的时间锚。私有 bot 留空,跟随听者的客户端时区。
- **配置 blob(`bots.config`)** —— 一份 jsonb,装所有「该可改、不该写死」的旋钮:复盘节奏、来信探索/协作模型、识图模型、语音模型与音色、网络搜索开关、模型盲盒揭示模式、模型池本身。前端 / board 改它,不进代码(见党纲红线「配置走前端」)。

**为什么**

- **模型池 ≠ 一对一绑模型**:模型迭代太快,把 bot 钉死在 `claude-x.y` 上,一个月就过时。让 bot 携带一个「按策略描述的池」,而不是一串很快会失效的具体 slug——**预设(top_flagship / 各家最新 / 最快 / 中文旗舰…)在对话时才解析成当下真实可用的模型**,bot 的「口味」就不会随模型下架而烂掉。这也撑起了[模型盲盒](../features/model-blindbox.md):每次抽到的可能不一样,正好拿来让人猜。
- **人格是长出来的,不是填出来的**:大绿豆是「朋友不是助手」,朋友的样子来自相处积累,不是注册时勾选的性格选项。所以人格层走记忆 / 手记,建 bot 时不强迫用户填人设。
- **config 走 blob 而非散落的列**:这些旋钮大多是「可选、按需出现、未来还会加」的,塞进一个版本化的 jsonb 比每加一个功能开一个列更稳;前端永远发「这个 key 的完整子对象」,后端整 key 替换。

**用在哪·长什么样**

- 建 bot:给名字 → 选模型(可以是一个具体模型,也可以是一个池 / 预设组合)→ 之后在 bot 设置里调那些旋钮(复盘、识图、语音、盲盒、时区、邀请管理…)。
- 聊天时:**主模型在每个新会话开起来的那一刻从池里抽定并钉在会话上**(`current_model_slug`),之后这个会话一直用它,除非用户手动换 / 重抽。盲盒模式下这个模型可能先藏着让人猜。
- 创建者改了 bot 默认(模型 / 旋钮)→ 通过 `/v1/bots/:id` 落库并立刻清掉 KV 里的 bot 缓存,下一回合即生效;**没有 per-会话 pin 的会话**才吃这个新默认。

**示例** — 你建了个叫「老张」的 bot,不想操心选模型,给它配了「各家最新旗舰」这个预设当池。今天和它开一个新会话,系统把这个预设解析成当下真实在线的旗舰模型集,抽中其中一个钉在这个会话上。下个月某家出了新旗舰,预设自动把它纳入候选——你什么都不用改,「老张」的池就跟着新了。

**边界**

- bot 之间**没有「好友」FK 关系**——「bot 的好友」永远指**人类**(谁把它加进了联系人)。bot 跨自己边界去找别的智能,走的是[委派](delegation.md)和[社交图](bot-social-graph.md)里的工具,不是「bot 加 bot 好友」。
- 人格层不是建 bot 时的必填项;没有「性格 / 语气」下拉框那种东西。
- 时区对私有 bot 无效——别把它当通用字段。

**注意**

- **vanity slug 已彻底退役。** 早期 bot 有个 `slug` 当公开身份 / 加入路径,现已**不再是产品概念**:bot = 显示名 + 自动 id。⚠️ DB 层 `bots.slug` 列**仍然存在且 NOT NULL**(历史列,预设 bot 还在用),但产品上没有任何地方把它当「可搜的 @名 / 加入路径」——别在文档或新功能里把 slug 当 bot 的对外身份(详见 [bot 可见性](bot-visibility.md) 与 [bot 邀请](../features/bot-invites.md))。
- **`config` 可由 iOS 直接经 RLS 写**(不只走 `/v1/bots` 端点),所以消费 config 的代码不能盲信形状——这是已知的「双写入口」,读取侧都做防御解析。
- 配置里有 `modelPool`(新)和 `arena`(旧客户端写的同义键)两个键并存;新代码读 `modelPool`,`arena` 是兼容尾巴。

**现状** — 🟨 **核心已落,部分未端到端验**。模型池 + 预设解析(对话时展开 + KV 缓存)+ 盲盒抽取 + config 旋钮 + KV 缓存失效都在代码里跑;model-roles(识图/语音/来信等角色默认)已收口进 board 可配并部署。盲盒/换模型的端到端真机冒烟仍是尾巴(需登录态 GUI 构建,见 progress #297)。
