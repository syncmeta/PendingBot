# Bot 可见性

> 一个 bot 对谁可见、谁能加它,只有**两档**:`private` 和 `public_invite`。核心权威 = 决策 D1 + 迁移 `20260527091508_drop_public_open_visibility.sql`。相关:[bot 邀请](../features/bot-invites.md)(加入路径) · [bot 社交图](bot-social-graph.md)(好友列表半公开) · [建 bot 与预设](../features/create-bot-presets.md)。

**逻辑**

- **`private`(私有)** —— 只有创建者能打开 / 对话。这是新建 bot 的**默认档**。它的「好友」实际上只有 owner 一个人。
- **`public_invite`(公有 / 邀请制)** —— 创建者 + **被邀请进来的人**能打开。「被邀请」是硬门:不在邀请名单里(`bot_invites` / 走邀请链接兑换过)的人,连读这个 bot 的资料都不行(RLS `is_bot_invitee` 把关)。公有不等于公开——它是「邀请制 + 留痕」,不是陌生人广场。
- **`private → public_invite` 是单向的。** 一个 bot 一旦公开,就回不去私有(触发器 `bots_guard_public_update` 锁死);公有后创建者还能改它的模型 / 旋钮 / 关停,但**可见性不可逆**。
- **预设 bot 是另一类** —— 系统预置、`creator_id IS NULL` 的 bot 对所有登录用户可见(给新用户开箱即用的样张),不走上面的邀请门。

**为什么**

- **删掉了「陌生人可加入」这一档。** 早期有第三档 `public_open`(任何登录用户都能加),已**整档删除**(连同存量 public_open bot 一起删,不迁移)。两个原因:(1) 它会把用户自建的 bot 泄进**所有人**的好友 tab;(2) 新的[社交图](bot-social-graph.md)让公有 bot 能用 `ask_friend` 越过 owner 去问别的好友——这套机制假设 bot 的好友集是**经过审核的真人**,`public_open` 是错误的原语。删它呼应党纲:「社交建立在信任上,不做开放广场」。
- **单向公开**:公开是把一个 bot 暴露给更多人的决定,降级回私有会让「已经加进来的人」的关系含义变得暧昧(他们还算不算好友?),所以一刀切成不可逆,语义干净。

**用在哪·长什么样**

- 建 bot 默认私有;想分享给别人时,在 bot 设置里**显式公开**(一次性、不可撤销),然后才能签发[邀请链接](../features/bot-invites.md)。
- iOS 好友 tab 的可见性过滤药丸里有「私有 / 公有」分类,对应这两档。
- 公有 bot 的资料(头像 / 名字)只对它的邀请圈与同群成员半公开,不对全网公开。

**示例** — 你建「老张」时它是私有,只有你能跟它聊。你决定让朋友也能用 → 在设置里把它**公开**(从此回不到私有)→ 现在可以签发邀请链接;朋友凭链接加入后进了「老张」的邀请名单,能打开它,他和你在「老张」的好友列表里互相半可见。一个**没被邀请**的陌生人,既搜不到「老张」、也打不开它——公有 ≠ 公开。

**边界**

- **slug 不是加入路径,也不是可见性的一部分。** 没有「按名字搜到一个 bot 就能加」这回事;加入永远走[关联到邀请者的不可枚举 token](../features/bot-invites.md)。
- 公有不暴露全局身份:陌生人无法搜索、无法凭名字定位一个 bot。
- 「私有」不是「加密 / 隐身」,只是访问控制——owner 自己始终能开。
