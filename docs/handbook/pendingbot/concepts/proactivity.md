# 主动性(次要特质)

> 「到点自己做」是大绿豆早期想做的姿态,后来弱化了——它**不再是产品灵魂、也不再是筛选新功能的尺子**(那把尺子换成了「知错 / 给真价值」,见 [定位](../vision.md))。但作为一个**次要特质**它仍在:bot 到点会自己复盘、自己出门看一眼。这篇只立这层心智;具体每一种主动行为的产品说明(怎么触发、长什么样)在 `features/` 里各自成篇。

**逻辑**

大绿豆区别于「等你提问的助手」的一点:它**不只在被 @ 时才动**。在两个方向上,bot 到点会自己动起来,而不是被动应答:

- **复盘 / 校正(对内,回看)** —— bot 回头审视已经聊过的内容,自己核对事实、给自己留备忘,发现错了就在合适时机主动澄清或补正。它在为「未来的自己」写笔记,而不是等你追问。这一条同时是「知错」这个**产品核心**的主动出口。实例 PRD:[主动复盘](../features/proactive-lookback.md)。
- **探索(对外,网上)** —— bot 主动去外面世界看一看,把它觉得你会关心的东西带回来,而不是只在你问的时候才搜。实例 PRD:[网上冲浪](../features/web-surf.md) / [来信信箱](../features/envelope-inbox.md)(探索的产出以「来信」的形态回流给你)。

两件事形态各异,但**同一种姿态**:bot 有自己的内部时钟,到点 / 到条件就自发行动,产物再以合适的方式找到你(融进下一句回复、变成一封来信)。

**为什么**

- **它给「朋友不是助手」添了一点温度,但不是兑现它的全部。** 朋友会主动想起你、不必每句都等你开口;一个只在被 @ 时才回话的东西会更像工具。所以保留这层主动姿态有价值。但「朋友」真正的兑现靠的是**知错、不谄媚、给真价值**(见 [定位](../vision.md)),主动性只是其中一个让体验更活的次要面,**不再被当成内核或筛功能的尺子**——这是相对早期定位的一次降级。
- **统一姿态而非两个独立功能:** 把复盘 / 探索看成「同一种主动姿态的两个出口」,而不是两个各自为政的功能,能保证它们在体验上是一致的(都不用催、都到点自己来、产物都自然找到你),也避免每个方向各搞一套触发 / 调度 / 回流机制。

**用在哪·长什么样**

- 用户**不需要做任何配置就能感到**主动性:聊着聊着 bot 会主动澄清之前说错的地方;打开 app 会看到一封 bot 主动写来的「来信」。
- 节奏 / 开关可调(比如复盘的轮次间隔、来信的探索模型),但「主动」本身是默认开的产品姿态,不是一个需要用户去开启的高级选项。

**示例** — 你和 bot 聊完一个话题就去忙别的了。过了一会儿,bot 自己回看刚才的对话,发现它前面引用的一个数据可能不准,默默给自己记了一笔;等你再回来说话时,它自然地在回复里补一句「对了,刚才那个数我再核了下,应该是…」。你没问,它自己做了——这就是主动性,落在「复盘」这个出口上。换个出口:它某天主动去网上翻到一篇你大概会感兴趣的东西,写成一封来信躺在你的信箱里。

**边界**

- **本篇只立心智,不写任何一种主动行为的实现 / 触发细节。** 复盘怎么触发、来信怎么探索,各自在 `features/` 里讲;别在这里展开。
- 主动 ≠ 打扰。主动性的产物要「自然找到你」(融进对话 / 进信箱),不是疯狂推送;克制是它的一部分。
- 主动性是**次要的产品姿态**,不是某一段代码——不要把它误当成「lookback runner」或「envelope runner」这种具体机制的同义词,更别把它捧回「产品内核」的位置(那是「知错」)。

**注意**

- **主动性已从「内核」降级为「次要特质」。** 早期定位把「到点自己做」捧成产品灵魂、当作筛选新功能的尺子;现在产品核心是「知错」,主动性退到一个次要面。读到旧 spec / 旧 README 把主动性当内核时,按 [定位](../vision.md) 校正。
- **「议论(一群 bot 谈你)」这个早期的第三出口已删。** 对应 feature 已物理删除,主动性现在只剩复盘 / 探索两个出口。bot 的社交能力(共养 / `ask_friend` 等**活**功能)仍在,见 [bot 社交图](bot-social-graph.md);只是「一群 bot 凑一桌议论你」这个产品形态不再立。
- 「网上冲浪」这个方向在实现上**经历过演化**:早期独立的 surf / scroll **runner** 已退役,**主动探索的产物统一归「来信(envelope)」**;但「聊天里现查现答」那一形态仍活在会话里。所以读到旧 spec 里的 surf / scroll runner 时,把它理解成「探索」方向的旧实现,现状看 [网上冲浪](../features/web-surf.md) 与 [来信信箱](../features/envelope-inbox.md)。(残留的 `surf_runs` / `scroll_runs` 死表见 `docs/tech-debt.md`。)
- 两个出口的**落地成熟度不一**(见各 feature 篇的现状标记);别因为「都是主动姿态」就默认两件事都已完整端到端可用。

**现状** — 🟨 **姿态成立,两个出口落地程度不一**。复盘 / 来信的机制都已在代码里(见各 feature 篇),但完整的端到端真机验证是 pre-launch 共同的尾巴。本篇作为心智锚点是 ✅ 稳定的(已校正为次要特质,非内核);具体可用性以各 `features/` 篇的现状为准。
