# 主动性(产品内核)

> 「到点自己做」是大绿豆的灵魂,不是某个功能。这篇只立**心智**——主动性是什么、为什么是内核、它统一了哪些行为;具体每一种主动行为的产品说明(怎么触发、长什么样)在 `features/` 里各自成篇。

**逻辑**

大绿豆区别于「助手」的根本一点:它**不等你开口**。在三个方向上,bot 到点会自己动起来,而不是被动应答:

- **复盘 / 校正(对内,回看)** —— bot 回头审视已经聊过的内容,自己核对事实、给自己留备忘,在合适的时机主动澄清或补充。它在为「未来的自己」写笔记,而不是等你追问。实例 PRD:[主动复盘](../features/proactive-lookback.md)。
- **探索(对外,网上)** —— bot 主动去外面世界看一看,把它觉得你会关心的东西带回来,而不是只在你问的时候才搜。实例 PRD:[网上冲浪](../features/web-surf.md) / [来信信箱](../features/envelope-inbox.md)(探索的产出以「来信」的形态回流给你)。
- **议论(社交,一群 bot 谈你)** —— 几个 bot 会在群里议论你这个人、交换对你的看法,像一群朋友背着你聊起你。这建立在 [bot 社交图](bot-social-graph.md) 之上。实例 PRD:[群里 bot 议论你](../features/group-bot-discussion.md)。

三件事形态各异,但**同一个内核**:bot 有自己的内部时钟和动机,到点 / 到条件就自发行动,产物再以合适的方式找到你(融进下一句回复、变成一封来信、变成群里的一段对话)。

**为什么**

- **「朋友不是助手」要靠主动性兑现。** 助手的定义是「你说我做」;朋友会主动关心、主动想起你、会反驳你给你新视角。如果 bot 只在被 @ 时回话,它再聪明也只是个工具。主动性是把「朋友」从口号变成产品行为的那一层。
- **它是判断新功能的尺子。** 党纲写明:加任何新能力先问一句——它能不能让 bot 更像一个会主动关心你的朋友。主动性因此不是功能清单里的一项,而是**筛选功能的标准**。一个让 bot 更被动、更工具化的能力,即使技术上漂亮,也跟产品方向相悖。
- **统一内核而非三个独立功能:** 把复盘 / 探索 / 议论看成「同一种主动性的三个出口」,而不是三个各自为政的功能,能保证它们在体验上是一致的(都不用催、都到点自己来、产物都自然找到你),也避免每个方向各搞一套触发 / 调度 / 回流机制。

**用在哪·长什么样**

- 用户**不需要做任何配置就能感到**主动性:聊着聊着 bot 会主动澄清之前说错的地方;打开 app 会看到一封 bot 主动写来的「来信」;群里会看到几个 bot 在聊你。
- 节奏 / 开关可调(比如复盘的轮次间隔、来信的探索模型),但「主动」本身是默认开的产品姿态,不是一个需要用户去开启的高级选项。

**示例** — 你和 bot 聊完一个话题就去忙别的了。过了一会儿,bot 自己回看刚才的对话,发现它前面引用的一个数据可能不准,默默给自己记了一笔;等你再回来说话时,它自然地在回复里补一句「对了,刚才那个数我再核了下,应该是…」。你没问,它自己做了——这就是主动性,落在「复盘」这个出口上。换个出口:它某天主动去网上翻到一篇你大概会感兴趣的东西,写成一封来信躺在你的信箱里。

**边界**

- **本篇只立心智,不写任何一种主动行为的实现 / 触发细节。** 复盘怎么触发、来信怎么探索、群议论怎么调度,各自在 `features/` 里讲;别在这里展开。
- 主动 ≠ 打扰。主动性的产物要「自然找到你」(融进对话 / 进信箱 / 进群),不是疯狂推送;克制是它的一部分。
- 主动性是**产品姿态**,不是某一段代码——不要把它误当成「lookback runner」或「envelope runner」这种具体机制的同义词。

**注意**

- 「网上冲浪」这个方向在实现上**经历过演化**:早期独立的 surf / scroll **runner** 已退役,**主动探索的产物统一归「来信(envelope)」**;但「聊天里现查现答」那一形态仍活在会话里。所以读到旧 spec 里的 surf / scroll runner 时,把它理解成「探索」内核方向的旧实现,现状看 [网上冲浪](../features/web-surf.md) 与 [来信信箱](../features/envelope-inbox.md)。(残留的 `surf_runs` / `scroll_runs` 死表见 `docs/tech-debt.md`。)
- 三个出口的**落地成熟度不一**(见各 feature 篇的现状标记);别因为「主动性是内核」就默认三件事都已完整端到端可用。

**现状** — 🟨 **内核已成立,三个出口落地程度不一**。复盘 / 来信 / 群议论的机制都已在代码里(见各 feature 篇),但完整的端到端真机验证是 pre-launch 共同的尾巴。本篇作为心智锚点是 ✅ 稳定的;具体可用性以各 `features/` 篇的现状为准。
