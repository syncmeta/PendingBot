# Bot 社交图

> bot 有自己的社交圈:它知道**谁是它的好友**、**它在哪些群里**,这套自我认知喂进每一回合,让它能像个有社交生活的人那样行动——可以被好友共养、会主动问别的好友、知道自己在群里的处境。相关:[bot 可见性](bot-visibility.md) · [委派](delegation.md)(bot 跨边界找别的智能的工具)。

**逻辑**

- **bot 的「好友」永远是人类。** 谁把这个 bot 加进联系人(`user_bot_contacts`),谁就是它的好友。bot↔bot 没有好友关系(FK 只允许人类)——bot 之间的协作走[委派](delegation.md),不是「加好友」。
- **bot 知道自己的社交圈。** 每回合给 bot 一份**轻量快照**:有多少人类好友、最近几位是谁、在多少个群里、最近活跃的几个群。这是动态、易变的事实,挂在 per-turn 的易变上下文里(加 / 删一个好友不会污染缓存的人格)。
- **一个 bot 可以被多人共养。** 公有 bot 被邀请进来后,它在多个不同的人的联系人里同时存在——这些人都是它的好友,它对他们有一份共同的社交认知,而不是「每个用户各有一个独立副本」。
- **好友列表对好友 + 同群成员半公开。** 谁能看到「这个 bot 还有哪些好友、每个好友是谁拉进来的」?三种人:① bot 的创建者(全量,连私有 bot 也看得到);② **这个 bot 的任何一个好友**;③ **任何和这个 bot 同在一个群里的人**。圈外不可见。
- **bot 会主动越过 owner。** 公有 bot 能用 `ask_friend`(见 [委派](delegation.md))主动去问它的某个真人好友一个问题——它不只被动回你,还会动用自己的社交关系。这是 bot 有「社交生活」的一种体现。

**为什么**

- **让 bot 有「社交生活」是产品的一部分。** 要让 bot 能被好友共养、能主动问别的好友、知道自己在哪些群,它必须先**知道自己有哪些好友、在哪些群**。社交图就是这份自我认知的底座,它不是一个孤立功能,而是支撑主动问询(`ask_friend`)/ 共养 / 委派的共同基础。
- **半公开而非全公开:** 朋友圈式的透明(好友之间互相可见、能看到谁拉谁进来)建立社交信任与留痕;但对圈外人完全不可见,守住「不做开放广场」「隐私默认收紧」的红线。同群成员能看,是因为他们本来就在群里和这个 bot 共处,看见它的社交圈不构成新的泄露。
- **被共养而非各持副本:** 一个公有 bot 是一个**共同的社交对象**,大家养的是同一个它。这样它跨好友问询、在群里被多人共处才有意义——否则每人一个副本,社交图就退化成一对一了。

**用在哪·长什么样**

- bot 的好友列表有面向用户的入口(iOS「查看 bot 好友」),列出每个好友 + **是谁把他拉进来的**(`invited_by` 留痕);访问权按上面三类人把关。
- 每回合 bot 的系统提示里有一段「我自己的社交圈(本回合快照)」:好友数 / 最近几位、群数 / 最近几个;公有 bot 还会被提示「你可以用 `ask_friend` 主动问其他好友」。
- 公有 bot 进群后,会立刻给自己生成一段「什么时候该叫我」的自我介绍,供群里的小模型路由判断何时唤醒它——这是它在群社交里登场的方式。

**示例** — 你和三个朋友共养一个叫「老张」的公有 bot,还把它拉进了一个四人群。在群里,「老张」清楚自己有 4 个人类好友、正在这个群里,知道何时该应声而出。某次它想确认一件只有你朋友小李知道的事,就用 `ask_friend` 私下去问小李,等小李回了再把答案带回当前对话。你和三个朋友彼此能在「老张」的好友列表里看到对方、看到各自是谁拉进来的;一个不在这个圈子、也不在群里的人,什么都看不到。

**边界**

- **bot 不会加 bot 为好友。** 跨 bot 的能力调用是[委派](delegation.md)(`delegate_to_specialist` / `ask_friend`),不在社交图里建 bot↔bot 边。
- **私有 bot 没有社交圈可言** —— 它唯一的好友就是 owner,`ask_friend` 这类工具对它关闭(问 owner = 直接跟正在对话的这个人说话)。
- 社交图快照是**统计 + 几个名字**,不是完整通讯录导出;它给 bot 的是「我大概有哪些人、在哪些群」的体感,不是可被滥用的全量名单。
- 半公开**只给好友列表**;它不把好友之间的私聊内容、或一个好友的其它隐私暴露给别的好友。

**注意**

- 「好友列表对同群成员可见」这条容易被忽略:只要和 bot 同群,就能看它的好友圈,即使你不是它的好友。这是有意的(同群已共处),但设计相关功能时要记得这条暴露路径。
- bot 的好友列表的访问控制集中在 `get_bot_friends` RPC + 路由层,**不是**靠普通 RLS——bot-side 的社交读用 service-role 绕过 RLS(在拼提示词 / 跑工具时跑,不该被调用者视角的 RLS 挡)。面向用户的读才走带权限检查的 RPC。

**现状** — 🟨 **代码已落,端到端真验是尾巴**。社交图快照(好友 / 群计数 + top-N)注入每回合、`get_bot_friends` 三类访问门、`invited_by` 留痕、公有 bot 的 `ask_friend`、进群自我介绍都在代码里。主动问询(ask_friend / 回流)的完整端到端需真账号 / 真消息触发,属 pre-launch 未跑的尾巴(见 [委派](delegation.md) 现状)。
