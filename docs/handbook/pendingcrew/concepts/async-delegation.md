# 异步委派 / 非阻塞协作

> 人和 captain **永远在高层**:控制方向与决策,不被执行细节拖住。规划 / 审阅 / 拍板留在高层,具体执行(写码、跑研究、查资料、对齐 drift)派给 session / 子 crew 在后台跑;**派完立刻回到高层,不等不阻塞**,执行完成时推通知,人再回头看结果、继续。这是「人深度参与控制」的关键机制——放大人对方向的控制力,而不让执行细节淹没人。相关:[驾驶舱](cockpit.md) · [人在回路](human-in-the-loop.md) · [Session ↔ 群聊通信](../features/session-crew-comms.md) · [治理模型](governance.md)。

## 逻辑

控制循环**永不阻塞在执行上**。把一件事拆成两层,人 / captain 只占高层那一层:

- **高层(人 / captain 待的地方)** —— 定方向、给约束、审阅产出、拍板。这一层永远是活的、可响应的;人随时能起新活、改方向、看哪条线到哪了。
- **执行层(派下去后台跑)** —— 写码、跑研究、查资料、把代码对齐文档 drift 这类**具体落地**,交给 session / 子 crew 在后台异步执行。

委派是**发射后即返回(fire-and-return)**:派一个活下去,控制立刻回到高层,**不守着、不轮询、不阻塞**。执行方在后台推进,到了关键节点(完成 / 卡住 / 有发现)**主动推通知**上来;人 / captain 在高层收到通知,再回头看结果、决定下一步。于是人能同时挂着多条执行线,每条都在后台跑,而人的注意力始终留在「方向与决策」上。

## 为什么

- **放大人对方向的控制,而不是淹没人。** PendingCrew 的定位是「人深度参与、控制」的创造控制台(见 [vision](../vision.md))。但「参与控制」≠「盯着每一步执行」——如果人必须守着每个命令、每次编辑,注意力立刻被执行细节吃光,反而**失去**对方向的掌控。把执行甩到后台、只在高层做决策,才是真的放大控制力:人管的是「往哪走、行不行」,不是「这一行怎么写」。
- **控制循环不阻塞,才能并行 + 不卡死。** 同步等待执行 = 一次只能推一条线,且人被钉在原地。异步委派让多条线同时在后台跑,人的高层循环始终可响应——这跟 [治理模型](governance.md)「委派层层下放、中央不被执行淹没」是同一条原理:每一级只做本级该拍的板,把具体活下放,自己不被下层的执行细节堵住。
- **「通知驱动回看」而非「轮询守候」。** 人不知道某条线什么时候到节点,与其守着,不如让执行方完成时推上来。推送(无轮询)是这条原则的体感保证——发完就走、有结果自然冒出来(见 [Session ↔ 群聊通信](../features/session-crew-comms.md))。

## 用在哪 · 长什么样

这条原则贯穿 PendingCrew 多处,落点都是「派完就走、完成推回」:

- **驾驶舱里看差、生 session 就走。** 你在期望文档上改一笔 → 驾驶舱冒出「期望 vs 现状」的差 → captain(或你)直接生一个 session 去补 → **控制立刻回到驾驶舱**,不守着那个 session;它把代码对齐完、刷新现状(见 [驾驶舱](cockpit.md))。
- **human-in-the-loop 的 `ask` 是异步的。** session 请人介入时,人**有空再答**——不是被强行打断、必须当场处理。请求挂在待决策列表,人在高层节奏里回它(见 [人在回路](human-in-the-loop.md))。
- **session ↔ 群聊全程推送、无轮询。** 谁在白板上发了关键节点,直接推给在听的各方;没人靠定时器刷。「派下去的活有进展」= 一条通知冒上来,不需要谁守着拉(见 [Session ↔ 群聊通信](../features/session-crew-comms.md))。
- **governance 里委派层层下放。** 父 crew 定边界、子 crew 本地试错;中央定方向却不被执行淹没——同一条「高层只决策、执行下放后台」的结构(见 [治理模型](governance.md))。

## 示例

你在驾驶舱里把某篇 spec 的「OTP 改成 6 位」改了,看到它和现状有差,直接生一个 session 派给 edge-crew 去补 —— 派完**立刻回到高层**,接着去审另一条线、又起了一个研究 session 让它去查竞品的做法。两条线都在后台跑,你没守着任何一个。过了一会,edge-crew 那条**推上来一条通知**:「代码已对齐、现状已刷新」;研究 session 也推回了结论摘要。你在高层依次回看这两个结果,拍板继续。整个过程你的注意力一直在「方向 + 决策」上,没被任何一次具体执行钉住。

## 边界

- **不是「全自动」放手。** 异步 ≠ 无人。人 / captain 仍在高层做规划与拍板,只是**不阻塞在执行**;该决策的地方照样要人决策(见 [人在回路](human-in-the-loop.md)「交互非审批」)。委派把执行甩到后台,不是把判断权也甩掉。
- **本篇立的是统一原则,不定具体机制。** 「派活 / 通知 / 回看」的具体形态分散在各 feature(驾驶舱看差生 session、`ask`、群聊推送),本篇只把它们**归纳成一条北极星**——「人始终高层、执行全异步、控制循环不阻塞」;各自怎么实现见对应页。

## 现状

🟨 **部分机制已落,「人始终高层、执行全异步」作为统一原则是规划 / 北极星。**

- ✅ **session 后台跑**:worker session 在后台异步执行、不阻塞人的主循环,已落地。
- ✅ **`ask` 异步**:人在回路的请人介入做成异步(人有空再答),代码全落(见 [人在回路](human-in-the-loop.md) 的现状)。
- ✅ **推送无轮询**:session ↔ 群聊去轮询、改全程推送,代码全落(本地单机真跑通,远端活体推送真机是尾巴,见 [Session ↔ 群聊通信](../features/session-crew-comms.md))。
- ⬜ **驾驶舱看差生 session 补差**:派活那条产品形态随 [驾驶舱](cockpit.md)(task #439)落地,当前规划。
- ⬜ **「人始终在高层、执行全异步」作为贯穿全局的统一原则** —— 已拍定为北极星,指导驾驶舱 / 治理 / 人在回路日后的设计;作为「一条统一机制」尚未整体成形。
