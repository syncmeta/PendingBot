## 0. 一句话

新用户注册后，系统会自动塞给他一套"开箱内容"——6 个预置机器人、几个新手引导会话、1 个预设群、外加一个"和自己聊"的机器人。**这套内容是项目早期临时塞的占位，从没认真设计过**，如今和 App 现状全面脱节：新用户的第一印象是残缺、过时、甚至一发消息就报错。本文把问题讲清楚，并列出需要产品一起定的内容，作为重做的起点。

**本文不含实现，工程在产品定稿前不动代码。**

---

## 1. 背景：这套"出厂内容"是什么

新用户第一次登录后，后台会自动为他生成一批开箱即用的东西，目的是让空账号不至于一片空白、并顺带介绍 App 怎么用：

- **6 个预置机器人**——直接出现在机器人列表里
- **几条"新手引导"会话**——某些机器人预先发一段话，介绍 App 的某个功能（相当于内置教程）
- **1 个预设群**——演示"拉多个机器人进一个群聊"
- **1 个"和自己聊"机器人**——每个用户私有一个，叫"我自己"

从引导会话的内容能看出，**这套东西原本的意图是一个"功能导览"**：每条引导演示 App 的一个能力（介绍 App、公开/私有机器人、选模型、群聊……）。方向对，问题是内容从没跟着 App 更新。

---

## 2. 现状：新用户现在实际会看到什么

把技术问题翻译成用户视角（以下均按生产库实测）：

1. **6 个机器人的名字是无意义的占位词**——Amet、Consectetur、Eiusmod、Lorem、Sit、Tempor（一组拉丁文乱数假文，等同"测试1/测试2"）。

2. **点开任何一个机器人聊天，开箱就报错**——它们绑的模型是早期手写的占位值（如 `claude-opus-4.7`、`kimi-k2.6`），格式不规范、版本也过期，发消息时路由必然失败。**这是最硬的伤：第一句话就发不出去。** 6 个机器人全中。

3. **"和自己聊"也一样开箱报错**——每个用户私有的"我自己"机器人，被同一段老代码绑了同一个失效模型（`claude-opus-4.7`）。功能本身是好的（已确认，见 §7），但绑的模型同样失效。

4. **一条引导会话会凭空消失**——一条名为"公有私有机器人"的引导，指向的机器人（内部代号 ipsum）已经不在出厂名单里了，于是这条引导在生成时被静默跳过、根本不出现。

5. **预设群会凭空消失**——预设群"Grok 和 Gemini 群"的两个成员机器人（内部代号 dolor、adipiscing）都不在出厂名单里，群因为没有有效成员而生成失败、不出现。

6. **3 个机器人是"哑巴"**——Consectetur、Eiusmod、Tempor 这 3 个有机器人、但没有任何引导会话，用户点进去是空的。

7. **现存引导的文案里提到的模型是旧的**——比如"介绍这个 App"那条里写着"Opus 确实贵"之类，和现在的模型体系、和机器人实际绑的模型都对不上。

8. **引导若涉及语音，会名不副实**——预置机器人默认不开语音通话，引导若介绍打电话功能，用户照着点会发现用不了。

> 小结：原本想做"功能导览"，但脚本、演员、道具（机器人名单、模型、功能开关）没同步，**现在是一份过期且半残的开机引导，且开箱即报错。**

## 3. 问题分级

| 级别 | 问题 | 用户感知 |
|---|---|---|
| 🔴 开箱即坏 | 6 个预置机器人绑的模型失效 → 聊天报错 | 第一句话发不出去 |
| 🔴 开箱即坏 | "和自己聊"机器人也绑失效模型 | 自聊同样报错 |
| 🔴 内容残缺 | 1 条引导（"公有私有机器人"）指向已删机器人 → 消失 | 引导不完整 |
| 🔴 内容残缺 | 预设群成员都已删 → 群消失 | 群聊演示没了 |
| 🟡 体验不一致 | 预置机器人用"整块"输出，用户自建的默认"逐条气泡" | 同一人的机器人风格不统一 |
| 🟡 文案过期 | 现存引导文案提旧模型名 | 信息陈旧 |
| 🟢 观感 | 机器人名字是拉丁占位词；3 个机器人无引导（哑巴） | 显得没做完 |

🟢 另有几项纯内部、用户无感、当前也不出错（计费归属字段、模型供应商字段为空等），工程会顺手对齐，**不需要产品操心**。

## 4. 一个绕不开的约束（会影响产品怎么设计）

**目前系统里，机器人没有"人设/性格"这个存储位。** 一个机器人能用来做出差异的，只有这几样：

- **名字**（显示名）
- **绑定的模型 / 模型池**（决定它"聪明程度"和风格倾向）
- **引导会话的开场白文案**（它"第一句说什么"）
- 之后和用户聊出来的记忆（动态积累，非预设）

也就是说——**所有机器人共用同一套底层人格模板**，没有"按机器人单独写性格"的地方。所以：

- ✅ 能轻松做到：给每个预置机器人起好名字、配不同模型池、写不同开场白来体现不同用途。
- ⚠️ 做不到（除非额外立项）：让每个预置机器人有**鲜明、固定、独立的性格人设**（比如"毒舌评论家""温柔助手"）并稳定保持。这需要先给机器人加"人设"能力，是另一块工程，不在本次范围。

**请产品基于"靠名字 + 模型 + 开场白做区分"来构思，而不是"靠独立人设"。** 若强需要独立人设，请单独提出，我们评估另立项目。

## 5. 需要产品拍板的内容决策

下面是重做这套出厂内容时、**必须由产品定的内容**。每条附了工程的默认建议，方便会上逐条过；产品可直接采纳或改。

### D1. 这套出厂内容的定位是什么？
- **A（建议）功能导览**：延续原意图，每个预置机器人 + 引导演示 App 的一个能力，目标"教会新用户用起来"。
- **B 开箱即用助手**：预置机器人是用户会长期真用的助手（如"写作助手""翻译"），引导只是顺带。
- **C 两者结合**：少量导览 + 少量真助手。
> 这条定了，下面才有方向。

### D2. 要几个预置机器人？分别叫什么、干什么？
- 工程建议：**控制在 3–5 个**，每个有明确用途 + 中文名（告别拉丁占位）。
- 需产品给出：每个机器人的**名字 + 一句话定位**。

### D3. 导览要覆盖哪些功能点？
当前 App 的主要卖点（供产品勾选/排序）：
- 模型池 / 盲盒（机器人从一池模型里自动选，可盲评 A/B）—— 当前主打玩法
- 公开机器人 vs 私有机器人
- 群聊（拉多个机器人进一个群）
- 语音通话 / 群语音
- 计费 / 钱包（要不要在引导里讲？）
- 其他（产品补充）
> 每个勾选的功能点，对应由哪个机器人 / 哪条引导来演示。

### D4. 每个预置机器人默认配哪种"模型池"？
系统现有 5 种现成的模型预设（机器人可挂一个或多个，对话时自动从中选）：

| 预设 | 含义 |
|---|---|
| 头两家旗舰 | OpenAI + Anthropic 的旗舰 |
| 中国旗舰 | DeepSeek / 通义 / Kimi / 智谱 / MiniMax 的旗舰 |
| 各家最新 | 每家厂商最新发布的 |
| 速度快 | 吞吐最高的 |
| 最热门 | 评分最高的 |

> 需产品为每个机器人选 1 个或多个。建议：用于"导览模型池玩法"的机器人挂 2 个以上，效果最直观。

### D5. 每个机器人的"开场白"讲什么？
- 需产品给出每条引导的**文案**。
- 工程建议：**文案不要写死具体模型名**（如"我跑在 Claude Opus 上"），改用功能化表述（如"我会自动帮你挑当前最合适的模型"），避免又一次过期。

### D6. 预设群保留吗？讲什么？
- **A（建议）保留**：作为"群聊 + 多机器人协作"的演示，群里放 2–3 个上面定义的机器人。
- **B 去掉**。
> 若保留，需产品给：群名、放哪几个机器人、群里的开场内容。（现存那个"Grok 和 Gemini 群"按旧模型命名，无论如何要重做。）

### D7. "和自己聊"机器人
- 功能是活的、可达的（已确认）。它现在叫"我自己"。
- 需产品定：名字保留"我自己"还是改；它的定位/开场白（如"这里是你的私人草稿区"）。
- 工程会顺手把它绑的失效模型一并修掉。

### D8. 输出风格：预置机器人用"逐条气泡"还是"整块"？
- 工程建议：**跟用户自建统一（逐条气泡）**，消除风格不一致。
- 产品如有理由让某些导览机器人用整块，可单独指定。

### D9. 语音：哪些机器人开语音？
- 若 D3 勾了"语音导览"，对应机器人需开启语音；其余保持关闭。
- 需产品明确：哪几个机器人作为语音演示。

## 6. 工程侧改动范围（供产品了解工作量，不需细看）

产品内容定稿后，工程侧大致要做：

1. 重写出厂机器人名单（名字 + 模型池 + 语音开关 + 输出风格）。
2. 把机器人从"绑单个固定模型"迁到"模型池"新机制（顺带根治 🔴 报错）。
3. **同样修掉"和自己聊"机器人创建逻辑里写死的失效模型**（它在一个后台函数里，和预置机器人是两处，但同一个病）。
4. 按新名单重写引导会话 / 预设群脚本，文案去掉硬编码模型名。
5. 统一输出风格默认值。
6. 顺手对齐内部字段（用户无感）。

工作量集中在"内容重写 + 数据迁移"，不涉及大的架构改动；主要瓶颈是**等产品把 §5 的内容定下来**。

## 7. 已核实结论（原"待核实"，已查证）

排查中有一处不确定，已用生产库 + 代码核实，结论如下：

- **"和自己聊"功能是好的，不会因历史遗留报错。** 早期它依赖一个全局机器人（ipsum），后来已改成"每个用户私有一个自聊机器人"的新机制，**不再依赖那个已删除的机器人**。原本担心的"自聊入口可能崩溃"是伪问题。
- **但核实时发现一个真问题**（已并入 §2/§3/§6）：新机制创建自聊机器人时，又写死了和预置机器人同款的失效模型，所以"和自己聊"也开箱报错。这条会一并修。
- **现状规模已用生产库实测校正**：实际会消失的是 1 条引导 + 1 个预设群（不是更早草稿里估的更多）；3 个机器人是哑巴。详见 §8。
