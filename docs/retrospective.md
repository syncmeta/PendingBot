## 一、你当时想做什么

最早那句自我定位是逐字的：

> **知道自己错了的 AI · 主动上网冲浪还要处处想着你**

那时叫 **BubbleBored**，野心是**信息基础设施级**的：让机器人作为一个节点真正进入人的社交网络、帮人组织散落各处的信息、把人从信息茧房里拉出来（"破茧"）。定位是**挚友 / 明镜**，不是助手。

后来收窄了两次，这两次是理解今天这个仓库的钥匙：

**第一次收窄（做三端的时候）** —— 产能全压在"先把一个能聊天的 AI 朋友做出来"，宏大那半基本没动手。

**第二次是主动校准（2026-06 那轮）** —— 明确挪了四样东西：

| 挪动 | 内容 |
|---|---|
| **主动性降级** | 从"产品灵魂 / 筛功能的尺子"降为次要特质。原话：它"当初是拍脑袋的特质、后来弱化了、实际也没做到位" |
| **知错升为核心** | lookback / 复盘从"一种气质"变成"产品要交付的那件事"。新尺子是：**这个能力能不能让 bot 更诚实、更知道自己的边界、给人更真的价值** |
| **价值 ≠ 拟人** | **"给人更多价值 ≠ 把自己装得更像人"** |
| **多了一个角色** | 移动端当 PendingCrew ↔ 人之间的**桥** |

北极星（破茧 / 组织信息）没删，但诚实标注为"还没做"。

**今天的产品形态**：iPhone / iPad / Mac 三端一套 SwiftUI 代码，五个 tab —— 消息 · 好友 · Crew · 来信 · 我。

## 二、你立过的信条

摘自 [`handbook/shared/charter.md`](handbook/shared/charter.md)（党纲）和 [`product-taste.md`](handbook/shared/product-taste.md)：

- **是朋友，不是助手** —— "朋友"的定义很具体：会指出你的错、给你新视角、不谄媚。不是有求必应。
- **大绿豆 sui generis，无可对标** —— **能被对标 = 已经有人做了 = 做它就没意义**。文档里永远不写"对标 X / 像 X 但更好"。
- **不重复造轮子，不碰技术红海** —— 这一条是后面一长串外包决策的**同一个根**。分工定义：**"我们做应用搭建与设计，底层工程交给专业的人。"**
- **社交建立在信任上，不做开放广场** —— bot 和群全部邀请制 + 留痕，隐私默认收紧。
- **减法测试**（唯一的 UI 尺子）—— *去掉这个元素，用户还能靠直觉懂吗？能就删。* 例：「还没有 crew」→ 直接**空**；加号图标不配"新建"二字；不显货币符号。
- **不为图省事埋雷** —— 任何绕过约束的临时方案必须立刻记 tech-debt 或加 fail-loud 校验。
- **已落地 = 已验证**，不是"代码写完"。

### 你亲笔的四篇（`docs/handwrite/`，全仓唯一没被 agent 二次加工的思考）

**《如何安排机组的组织架构？》**
- **"能不分权就不分权"** —— 除非分工后上下文有大增长，否则协调成本和信息失真的风险更大。分工只为两个目的：① 强制专人做审阅 / 监督这类自己做会有偏颇的事；② 上下文窗口不够。
- **民主集中制**给 Agent 用效率可能很高（Agent 没有利益集团、不要求公平），但**高度依赖高层决策的科学性和信息的真实性**。
- 为这两个依赖设计了两个缓解机制：**信访**（高层联系方式对全组织公开）和**巡查**（长上下文模型直接下去读底层原始数据）—— 明确挂在**哈耶克的知识难题**上。**这是全篇最妙的洞察**：现实里集权破不了哈耶克难题（只能靠逐级失真的上报），但长上下文模型可以绕过汇报链自己看一手事实。
- **特区与市场** —— 集权适合目标明确的任务；方向本身要试错的必须有特区。配套设计：任意机组可跨层级直接向高层汇报，保护特区的信息隔离与试错空间。

**《民主集中制》** —— 记下了这套模式的天敌：

> 「但放在 Agent 身上有一大问题就是**谄媚**。大模型太会拍马屁了，另外它们**太容易被人牵着鼻子走了**。**特别是后者影响很大。这对协作中的人类要求很高。**」

**《评价和责任体系》** —— 几乎每句都是判断：

> 「我发现**对 Agent 强调要对什么负责、担责这种办法效果很差，它很容易畏手畏脚**。也尽量不要老去问责它…**而且这会让它学会伪装**。也不要老让它无私忘我、舍己为人…**同样会表演给你看**。
> **得让它的利益和集体的利益绑定在一起，把私利和公利对齐**…**能靠利益对齐就不靠监督手段**。」

以及对创新来源的判断：非特区机组市场化不充分，创新得靠**贝尔实验室式的卓越同行压力**而非市场激励 —— 所以在 crew 里放一些纪律较高的文档和范例，哪怕跟本机组的事不完全相干。

**《开发计划》**（全文四行，你当时的路线）：

> 先写文档，看看有哪一块缺，确定产品形态 → 把 pendingcrew 和 pendingbot 临时剥离 → 和 agent 商讨怎么做 → 让它开干，期间写网站。

**四步都执行了**：handbook 85 篇期望页写完、PendingCrew 8-17 真的拆成独立仓库、官网也在做。

📌 **一个值得单独指出的连接**：你在《民主集中制》里把 **Lookback 当成"内部如何科学决策"的答案**（"吾日三省吾身"，用不同能力特性的模型互相评价）。这解释了为什么"知错"能从一个气质升格成产品内核 —— 它在你脑子里从来不只是 bot 的一个功能。

## 三、你想出来的机制

**bot 的人格是长出来的，不是填出来的** —— `bots` 表里**根本没有人格字段**。bot 的"我是谁"由 Honcho 观察它自己说过的话反推出来。之所以可能，是因为 Honcho 的 peer 模型把 bot 当**平等 peer**（里面没有"用户 / 助手"之分）。冷启动无记忆时回落一段 `identity-quest` 提示词，让它自己去探索"我是谁"。

**主动复盘（lookback）= 知错唯一的主动出口** —— 每聊 N 轮（默认 10，按 **(bot, 用户)** 跨会话累计），bot 回看最近的对话，核查"我哪说糊涂了、你哪有盲区"，写一条**只给自己看的**笔记，下一轮自然带回来。几个细节全是产品判断：**没东西可说就闭嘴**（宁可不说不凑废话）· 旧笔记一并喂进去避免重复 · 讲完即弃（bot 自己标记退场）· 能手动催一次。

**模型盲盒**（一次很漂亮的转向）—— 原本是 A/B 盲投竞技场 + Elo → Bradley-Terry 排行榜。判断"让普通用户去评价模型"既不好玩也不留存，于是把**同一个机制**（用户不知道背后是哪个模型）转成**猜谜**：会话抽一个模型固定住、显示成 `PendingModel`，猜中或放弃才揭晓。arena 连根拔。顺带捡了个便宜：会话内固定模型对 prompt cache 友好。

**委派** —— 两条**性质不同**的路径：`delegate_to_specialist`（换个更强的模型跑一次独立补全，专家看不到历史、没有工具）+ `ask_friend`（私下去问一个真人好友，只有公有 bot 能用）。归在"知道自己的边界"下面，不是"能力增强"。回流的分寸也是产品判断：发起方会话活跃 → 答案融进下一句回复；不活跃 → bot 主动开口 + 推送。

**来信** —— 探索的产物是**一篇文章**，不是一条消息。两个角色一主一辅（explorer 规划执行 + collaborator 每轮搭一句），理由是"模拟一个人一边查一边有同伴搭话的探索过程"。**"宁可不写"是硬规矩** —— 素材不足就删除、不进 tab，不留"这次没写"的占位。

**每人一码的邀请** —— 群邀请码不是"群的码"，是**关联到签发者本人的码**。用起来一样（扫了就进这个群），但每份码不同，天然留痕"谁是被谁拉进来的"。bot 邀请同一套哲学。

**富感知**（想清楚了但**一行代码没写**）—— **价值 = 能力 × 契合度**。举例：*名医的价值大半在"他知道你的病史"；朋友的价值大半在"他知道你刚分手，所以不提你前任"*。三层：① 感官一直开着（"**相关性是事后才知道的，没开的感官不可能触发『该换个方向』**"）② 派生 stance（不是情绪，是姿态：不说"我觉得难过"，而是"综合我感知到的，此刻少折腾、先接住"）③ 素养（养出来的，不是塞进 prompt 的）。**最妙的一句：富感知和知错是同一个正反馈环**（感知 → 行动 → 回看 → 长素养 → 感知更准），所以素养不用另起系统，直接接在 lookback 这条已有的线上。

## 四、你拍过的板

### 4.1 否定式决策 —— 最容易忘的一类

想清楚了才**没做**的事。忘了就会被当新点子重提。

**钱**
- 不自研计费引擎（MoR / 退款 / 对账 / IAP 全是非核心复杂度）
- 不直连 Stripe（要 MoR 挡在前面）· 不自托管 Polar（自托管就失去 MoR 资格）· 不用 Lemon Squeezy（已被 Stripe 收购）
- **不收 BYOK** —— 余额 / 节流 / 群分摊 / 退款全建立在"平台掌握成本"之上，额度一旦来自用户自带 key，这套就散架
- **不提现成现金**（规避金融服务性质的合规风险）
- 不在每次扣费时加 markup（加价口径漂移会让成本对不清；markup 只在卖充值包时体现）
- 不做群内任意转账 / 指定第三方收款

**社交与隐私**
- 不做 `public_open`（陌生人可加入档）· 不做 slug-as-public-identity（与邀请制 RLS **正面冲突、ship 即坏**）
- 不做开放广场 / 陌生人可搜的公开身份 · 不做按昵称模糊搜人（只能用 handle 精确查）
- 不让 bot 加 bot 为好友（跨 bot 能力走委派）

**范围**
- **不做任务路由**（"该派给哪个模型 / agent"）—— 又难又一堆人在做；PendingCrew 的优势在"**把异厂个体编排到一起协作**"，不在路由算法
- 不碰技术红海 · 不做端到端加密（边缘投影需要明文）· 不搞 staging / 多环境 · 不在中国大陆上架
- 不做自定义 RBAC / multi-owner（三级固定角色）
- 不做 PendingCrew iOS（iPad 无子进程能力）· 不做本地 ↔ edge 双主同步（改一次性"毕业"）
- **不做"一句话帮你做 X"的通用 agent** · 不让 bot 假装是人 · 不写"对标 / 竞品"

**后台与看板**
- 后台不做应用内登录（身份唯一走 Cloudflare Access）· 不做自制运营仪表盘 / 不自建 VPS · board 不做运营仪表盘（分给 PostHog / Polar / PendingCrew）

### 4.2 钱这块设计得最细

**Subject（责任主体）** —— 一个 `responsible_subject_id` 同时回答三个问题：**谁付钱、谁可见、谁批准**。理由：*"它们本就该是同一个主体，拆开就会出现『A 付钱但 B 能看』『谁都能花但没人能批』这类裂缝。"* 只有两类 subject：`user_account` / `group_account`，没有第三类。

**群账号轻到"出门旅游都值得建一个"** —— 明确对照 Notion workspace 那种重资产。⚠️ 极易记混：**群账号 ≠ 群聊**，它可独立于任何群聊存在。

**实缴 vs 认缴**

| 模式 | 钱在哪 | 何时真扣 |
|---|---|---|
| 实缴 deposit | 真转进群钱包 | 注资当下转入，之后从池里扣 |
| 认缴 pledge | **不动，留在个人钱包** | 只是授权额度；群消费发生时按比例从个人余额当场扣 |

有效认缴 = `min(你认缴的, 你当前余额)`，实时算。于是"**一个人欠费不拖垮整个群**"自动成立：余额见底 → 有效认缴变 0 → 自动退出本轮分摊，不欠群钱、不连累别人。实缴那半走**质押池 + 份额衰减**（像 DeFi 质押池）：群消费只更新池子一行，不用为每笔消费写 N 条成员账。**每人占比这一个数，同时是分摊比例、也是可取出比例。**

**PNC = 27:1** —— 故意不是 100 / 1000 这种好心算的整数，**为的是降低消费痛感**。这是产品不变量，别改回去。

**WalletDO 为什么必须存在** —— Polar 余额最终一致、刷新约 10 秒（实测），进不了"每次 LLM 调用前判一下"的热路径；用 KV 也不行（余额是高频递减计数器，最终一致 + 后写覆盖会丢扣减、会超支）。

## 六、你撞过的墙

### 元病根：这个项目最常撞的墙叫「静默」

比记住任何一条具体 bug 都有用：

| 形态 | 实例 |
|---|---|
| **静默降级** | 客户端拿不到 token 就用 anon 发写 · MCP 拿不到密钥就不带鉴权头照常发 · 读成本的函数"没配密钥"和"查不到"共用同一个返回值 `null` |
| **静默丢弃** | codex 丢掉未建模的 server-request → 回合永挂 · zod 把 `reply_to` strip 掉 |
| **静默清空** | 白板解码失败 `(try? decode) ?? []` → 下次追加原子重写 → 历史永久丢失 |
| **静默回滚** | 线上 worker 比仓库新，一次 deploy 把生产退回三周 |
| **静默截断** | 列表硬编码 `.limit(500)` 无 has_more · AI Gateway 日志只扫最近 100 条 |
| **静默不生效** | `BILLING_ENABLED:"false"` 被 KV override 覆盖 · webhook 密钥没部署 → 恒 501 → 改了 prompt 线上可能长期不生效 |
| **静默通不过** | 编译期合法、运行期降级：修饰器顺序盖掉代码块样式 · 视图图外求值让 `@EnvironmentObject` 永不灌注 · `.task` 晚一帧 |
| **注释是错的前提** | 「subjects 与 user id 共享 WalletDO 键空间」（不共享，导致付费阻断）·「RLS 仅本人」（RLS 根本没开）·「等 webhook 随后补全」（那个 webhook 从未创建）·「resyncInspectorDivider 兜底」（该函数从未存在） |

**每一条"注释是错的前提"都直接造成过一次真实故障。**

### 五件最该重读的

**① 三轮误诊** —— 模拟器注册报 `permission denied for table users`，先后归因到 Keychain entitlements → 后端 bootstrap RPC → supabase-swift 静默 anon。**真因是 `project.yml` 对模拟器关了签名** → ad-hoc 构建拿不到 keychain access group → Keychain 全挂 `-34018` → 会话存不住 → 写降级 anon → anon 对 users 表只有 SELECT。钉死它靠的是线上 `SET ROLE anon` 直接复现出一模一样的报错。
**沉淀的判据**：`permission denied for table X` = **表级 grant 被拒**（RLS 被拒会说 `new row violates row-level security policy`）。

**② 会话列表投影烂尾了两个多月** —— 关于这件事**流传的说法是错的**：撤掉的是**推送**触发器（`realtime_notify`，往边缘扇消息的那个），**维护**触发器 `messages_unread_after_insert` 全仓零 DROP、至今在跑，DB 仍是正典写入方，边缘 DO 只是读缓存。5-29 撤扇出时承诺"改由边缘自己发"，**边缘那半直到 8-19 才真接上**。中间新建的会话在列表里是一个永远等不到补全的空壳。
修它时留下的两句：**"一个永远等不到补全的占位行，比没有这一行更糟"**；**"这个 bug 能活两个多月，正是因为通道断了从来没有人喊过一声。"**

**③ 「Mac build 绿」骗了很久** —— 早期 Mac 编译成功只是因为编译器在前两个错误就 abort，后面 100+ 个 `import UIKit` 的文件根本没参与编译。后来的宽屏三列壳"自合并起从未真正跑通过"。

**④ 围栏代码块两个多月完全不渲染** —— 暴露的真问题是 **PendingBot 至今一个测试 target 都没有**。

**⑤ 白板历史被静默清空**（7-17 真实数据丢失）—— 修法三件套：解码失败先归档损坏字节再 fail-loud、逐条容错解码（坏一条丢一条不连坐）、flock 互斥消除多进程 read-modify-write 竞态。

### 被反复证明有效的做法

1. **先加诊断日志再试第二次** —— 语音走网关那次，三次盲目回滚 vs 一次带诊断的尝试就定案
2. **用不依赖 UI 的 harness 复现** —— 一刀把"怀疑底层"切成"确认是 UI 层"
3. **`SET ROLE` + `has_table_privilege` 直接复现** —— 把三轮误诊钉死在一个角色上
4. **回滚事务里复现失败、再验证修复** —— 删除级联这类只有真删才暴露的改动，别凭静态分析宣布修好
5. **先 dump 真 schema 再写 builder 和测试** —— 否则测试会照抄你的印象，给你假绿
6. **还原规则先证后用** —— 从线上账本捞迁移前，先拿已有文件做往返 diff，逐字节一致才敢用
7. **fail-loud 优于兜底**
8. **口径诚实** —— 推断就说是推断（投影线上验证明确写了"这是从调用链推断，不是直接读到内容"）

### 危险区

1. **配置文件会骗你** —— `wrangler.jsonc` 写 `BILLING_ENABLED:"false"`，线上 KV `cfg:feature-flags` 是 `{"billing":true}`，判定是 `KV override ?? env` → **实际开着**。例外：Sentry 只认 env、不受 KV 覆盖 → **三个开关判断方式并不统一**。任何"计费当前是关的"推理都是错的。
2. **数据出了 Postgres 就没有 RLS** —— edge 手工把权限规则重写了两处，目前实现安全，但**"两边必须对齐"没有任何测试守着**。
3. **1v1 的对话历史完全由客户端上传，服务端不校验** —— 构造请求即可让 bot 相信任意历史，包括伪造它自己说过的话。对照：群聊由服务端自查最近 20 条，所以这不是做不到，是为省一次查询的取舍。
4. **客户端的写门只有注释在守** —— 28 个写点全部合规（逐点核过），但这是约定性不是结构性的。
5. **客户端 ↔ 边缘错误契约有三个破口** —— 402 余额不足不走信封（iOS 只能子串匹配 `insufficient_balance`）· 401 和 429 也不走 `{error:{code}}`。
6. **三端零自动化测试** + `runTitle` 的标题级联**永远 free 从不计费** + 计费门禁到处 fail-open（8-18 事故后的刻意选择）+ **DLQ 刻意不消费**。
7. **线上 14 条代码零引用的 secret**，含一条**名字本身就是明文 Daytona token**、以及仍活着的 `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_ANON_KEY`。
8. **限流形同虚设** —— 全仓 5 个调用点共用同一个 30 次 / 60s 计数器；**发消息、上传完全没有限流**。
9. **prompt 三层全空 = 整条对话链路 500**（有意设计，无 bundled fallback）；而 `LANGFUSE_WEBHOOK_SECRET` 未部署 → prompt 变更推不进 KV，KV 又无 TTL → **改了 prompt 可能长期不生效**。

### 环境：开箱能跑

bun 1.3.11 / xcodegen / Xcode / supabase CLI（已 link）/ wrangler（在 `apps/edge/node_modules/.bin`，已登录）/ docker 全在，依赖都装着，`main` = `origin/main` 零未推提交。edge `typecheck` exit 0、`vitest` 79 文件 681 测全绿（实跑）。

**两个文档没写的隐含前提**：
- **新 clone / 新 worktree 必须先跑一次 `xcodegen`** —— 仓库里没有 committed 的 `.xcscheme`，否则 `-scheme PendingBot` 直接找不到。
- **验登录态必须 Xcode GUI 构建** —— headless CLI 会回落 ad-hoc 签名，Keychain 照样挂。
